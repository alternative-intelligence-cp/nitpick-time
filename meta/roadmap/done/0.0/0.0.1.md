## 2. Decisions taken at planning

- **P-7 — one placeholder module per directory, and it parses.** An empty
  directory is invisible to the `parse` sweep, and the sweep is what stops the
  grammar being quietly made partial. Each is `src/<dir>/<dir>.npk` with
  `mod:<dir>;` and a header comment naming the specification section that will
  fill it and the cycle that will do it. They are replaced, not deleted.
- **P-8 — `src/lib.npk` re-exports deliberately, one line per public name.**
  `use` is not transitive (`MODULE_REFERENCE.md` §2.3), so the surface is a
  list a reviewer can read in one file. That is a feature and the reason the
  library has an umbrella at all.
- **P-9 — the consumer test imports by relative path** (`specs/BUILD.md` B-16)
  and carries a comment naming O-N1 as the reason, so the day dependency roots
  work, the thing to change is greppable.
- **P-10 — CI pins the compiler by commit**, not by branch. The compiler is
  moving through cycle 1.5; a library whose CI tracks its `main` is a library
  whose CI breaks for reasons that are not its own. Bumping the pin is a
  deliberate commit that runs the full suite.
- **P-11 — the placeholder for `src/host/` carries the purity comment from
  day one.** It is the module every other file is forbidden to import
  (`BUILD.md` B-17), and the header saying so is what a reader meets before the
  rule is enforced by a check at 0.3.

## 3. Steps

1. **The module skeleton.** Six placeholder modules, `src/lib.npk`, and the
   layering comment in each header naming what it may import
   (`specs/BUILD.md` §6's diagram). Commit.
2. **The consumer.** `tests/conformance/import.npk`: `mod:import;`,
   `use "../../src/lib.npk".*;`, a `main` that exits 0, a `failsafe` with the
   system arms. It compiles against an empty surface, which is the point — it
   keeps compiling as the surface grows, and the day it does not, the surface
   changed incompatibly.
3. **`nitpick.toml`.** The first `[[test]]` entries: `probe` (stage `program`,
   `tests/probe`) and `conformance` (stage `compile`, kind `positive`).
4. **CI.** A workflow that: checks out `ntime`; checks out the compiler at the
   pinned commit; installs LLVM 20.1.2; builds the compiler; runs
   `harness/run.py` (a stub until 0.0.2, which still must exit 0). Runs on push
   and on pull request.
5. **`CLAUDE.md` and `CONTRIBUTING.md` reviewed.** Both were written at
   repository setup, before the probes ran. This step re-reads them against
   0.0.0's verdicts and extends the reserved-word list and the "four things
   that will surprise you" with whatever the probes actually cost.

#### 2. The measurement that is worth more than the code

**`tests/conformance/import.npk` and `tests/probe/probe11d_floor_only.npk`
emit BYTE-IDENTICAL IR — 845 282 bytes, `diff` exit 0, zero differing lines.**

Not merely the same size. Identical. Both declare only `main` and `failsafe`,
which are root-level and unqualified since D-248, so neither file contributes a
module-qualified symbol and the whole `.ll` is the fixed per-program prelude
cost. Two consequences:

- **Importing `ntime` today costs a consumer exactly nothing** — no bytes, and
  no arms beyond `SAFETY.md` S-4b's floor of four. That is not read off the
  compile: the negative control, the same file with `WildLeak` deleted from its
  `failsafe`, is `NITPICK-REACH-002` at exit 1. The four arms are genuinely
  required.
- **The day `src/lib.npk` exports its first name, these two files must stop
  being identical**, and that divergence is the first observable evidence that
  the surface became real. Written into `tests/conformance/README.md` so the
  next session inherits the instrument rather than the number.

Both files are canaries for the compiler's 1.5.2d (D-262). **That number is
expected to move at that landing and a change there is the landing, not a
regression.**

The optimised leg was run too (B-3): `opt -O2` → `llc -O2` → link → run, exit 0
both ways.

#### 4. The dispatch's own claims, re-measured

**One was false as stated.** The claim relayed was that `probe09_environ_split`
run with `TZ=Europe/KIEV` "still exits 0". It does not — it exits **34**,
because `'V'` is not `'v'` at `hb[vhi - 1]`.

**The underlying point was right, and the spelling that demonstrates it is
`Europe/Kiev`.** Measured across six values of `TZ`, before any change:

| `TZ` | probe09 | probe09b |
|---|---:|---:|
| unset | 30 *(dedicated)* | **10** *(substantive)* |
| `Europe/Kyiv` | 0 | 0 |
| `Europe/Kiev` — the old IANA name | **0** | **0** |
| `Europe/KIEV` | **34** | **13** |
| `UTC` | **31** | **10** |
| `America/New_York` | **31** | **10** |

The `Kiev` row is the sharp one: **both probes passed at exit 0 under the wrong
zone name**, because everything either checks — 11-byte value, `'E'`, `'u'`,
`'v'`, `'/'` at offset 6, and for 09b a 14-byte entry with `'E'` at 3 and `'v'`
at 13 — is equally true of `Kiev` and `Kyiv`.

**And probe09, the file held up as the model, had a quieter version of 09b's
own defect.** Its `exit 30` covers `TZ` *absent*, which is why it was the
model; `TZ` *present and wrong* landed on 31 and 34, both substantive. Fixed in
both files under **TM-116**: **30** absent, **39** present-and-wrong, dedicated
in both, and in `probe09b` the precondition is checked by `tz_index`, a helper
that returns an **index and never a view** — deliberately, so the check cannot
be answered by the very mechanism under test.

**One other dispatch claim was wrong and harmless:** `tests/probe/` does have a

#### 8. What is NOT done

**CI has never been seen green**, because 0.0.1 does not push (`ROADMAP.md`:
commit after every subcycle, push at the end of every cycle). The workflow is
written, its YAML parses, and all six `run:` blocks pass `bash -n`. The
acceptance item is marked `[~]` rather than `[x]` and carries to the push that
closes 0.0.

**The digest check reports rather than asserts, deliberately.** The pin's
provenance note records that its `npkc` was built by `npkg build` on this
workbench; CI uses the bootstrap harness's builder, which is the recipe a
sibling library has actually seen go green in Actions. Cross-machine byte
identity of a *linked binary* is a strictly stronger claim than D-078/D-204's
reproducibility rule, which is about emitted **IR** from different working
**directories**. Nobody has measured the stronger claim, so CI prints both
digests beside the workbench's and a later commit may promote it to an
assertion naming the run that measured it. Asserting first would make the first
red run ambiguous between *"the pin is wrong"* and *"CI's linker is not this
laptop's"*, which is the worse of the two.

### 1.2 0.2.0's test gap, re-measured — and why step 1 reorders two checks

**The unit as 0.2.0 left it**, read from its record commit `e0e8547`, against a
`span` whose `instant_add` writes `clock: InstantClock.Monotonic` instead of
`clock: t.clock`: **exit 0 on both legs** (block 0b's next-to-last line). Its exit 14
compares `instant_add`'s clock with `Monotonic`, which is `InstantClock`'s first
variant — tag 0, the value a hard-coded default or a vacant read produces (the
workbench `PLAYBOOK.md` §9) — so the check cannot tell the clock was kept. 0.2.0's
plan saw exits 11, 13, 16 and 17 red on mutants and its worker 15; **10, 12 and
14 never had one**, and the unit's header said each exit had.

The fix is a `Boottime` reading through `instant_add` and through the `Vec`. And
its place is measured, not chosen: the same unit against an `instant_add` that
hard-codes `Boottime` exits **12** on both legs (block 0b's last line) — `c`
becomes a `Boottime` reading, and `instant_cmp(c, b)` refuses a pair from two
clocks before exit 14's check is reached — so a clock check that stays after the
comparison can never fire on that mutant. **Step 1 moves both clock checks ahead
of the comparison**: hard-coding `Boottime` then exits 14 at the first, and
hard-coding `Monotonic` at the second (block 1).

### 1.3 The candidate type and constructor — what a consumer can do

§4.2's module, compiled as a root: **`npkc` exit 0**. `m_use`, a consumer of
`span` and `core/vec`: builds `-1 s, 500 000 000 ns` — half a second before the
epoch — through `timestamp_of`, reads both fields back, compares `0 s, 0 ns` with
it through the derived `cmp` (`Greater`), has `0 s, 1 000 000 000 ns` refused, and
reads the value back through a `Vec<Timestamp>`: **exit 0 on both legs**. Without
`Copy` in the derive, `m_use` is `NITPICK-TYPE-017` at its five `Vec` sites — the
declaration, its turbofish, `vec_push`, `vec_at` and `vec_free`, `Vec<T: Copy>`
since 0.2.0b; without `Ord`, its `cmp` is `NITPICK-TYPE-019`. **An `Instant` and a
`Timestamp` are 16 bytes each, and an `InstantClock` 4** — measured as exit codes,
so the numbers cannot be transcribed wrongly.

The constructor's own behaviour is the units' (§4.3): over the cross product of
eleven `secs` and twelve `nanos` at and around every bound, it accepts the 35
pairs inside both ranges and refuses the 97 others, each accepted value handing
back what it was given, both legs; and the eight-value chain of
`timestamp_order.npk` orders as the instants it spells. Block 4 re-runs both and
every mutant of §3's step 4.

### 1.4 What a consumer cannot do — the seal

| Program | Verdict |
|---|---|
| `m_literal` — `Timestamp{ secs: -1i64, nanos: 1500000000u32 }`, half a second after the epoch spelled the second way | **`NITPICK-TYPE-079`**, once per sealed field — two reports at the literal's one position. Under B-7c the probe names the code twice; the compiler's DEF-165, registered open, would make it one |
| `m_write` — `t.nanos = 1500000000u32;` on a `Timestamp` from `timestamp_of` | **`NITPICK-TYPE-079`**, once |
| `m_literal` again, against the module with TM-011's fields as written — unsealed | **compiles** — the second spelling, built by any consumer in one line |

So the constructor is the only way a consumer holds a `Timestamp` — which is what
makes the constructor's property test `VERIFICATION.md` P-4's stand-in (PD-65).

### 1.5 M-3 at the type, both ways — and through `=>!`

| Program | Verdict |
|---|---|
| `m_i_cmp` — `t.cmp(a)`, an `Instant` where `Timestamp`'s comparison takes a `Timestamp` | **`NITPICK-TYPE-007`**, *"expected `Timestamp`, found `Instant`"*, at the argument |
| `m_i_param` — the same, at a function of the consumer's own that takes a `Timestamp` | `NITPICK-TYPE-007` |

So nothing a consumer writes converts one to the other, but storage it
reinterprets itself — the opt-out `CALENDAR.md` C-8c states for every checked
property, which PD-66 records and does not assert. The two cast directions are
two questions: `=>!` narrows an integer to an enum (the compiler's D-140,
`SAFETY.md` S-15c), which is what `Timestamp` → `Instant` would do to a clock
tag, so a later rule could admit one direction and not the other.

### 1.6 `hidden`, and question 15

With `Instant`'s `ns` and both of `Timestamp`'s fields `hidden` instead of
`sealed`, `m_hreads` — a consumer reading `a.ns` and `t.secs` — is
**`NITPICK-TYPE-080`** at each read (the compiler's D-314). And `m_mono`, a
consumer calling the floor's `mono_now()` twice, **compiles**: the builtin is
`() → int64`, `CLOCK_MONOTONIC` nanoseconds (the compiler's
`BUILTIN_REFERENCE.md`). So hiding `ns` would close nothing — a program has the
raw number either way, which is question 15's answer, now measured — and it
would cost every reader of an `Instant` or a `Timestamp` outside `span` an
accessor.

```nitpick
mod:span;

use "../cal/cal.npk".ETimeValue;
use "../core/limits.npk".NTIME_SECS_MIN;
use "../core/limits.npk".NTIME_SECS_MAX;
use "../core/limits.npk".NTIME_NANOS_PER_SEC;

#[derive(Eq, Clone, Debug, Copy)]
pub enum:InstantClock = { Monotonic; Boottime; };

#[derive(Eq, Clone, Debug, Copy)]
pub struct:Instant = { sealed int64:ns; sealed InstantClock:clock; };

pub func:instant_of = Instant(int64:ns, InstantClock:clock) never fails {
    pass Instant{ ns: ns, clock: clock };
};

pub func:instant_since = Duration(Instant:later, Instant:earlier) {
    if (later.clock != earlier.clock) { fail ETimeValue; }   // ValueFault.ClockMismatch
    pass raw duration_ns(later.ns - earlier.ns);
};

pub func:instant_add = Instant(Instant:t, Duration:d) never fails {
    pass Instant{ ns: t.ns + d.ns, clock: t.clock };
};

pub func:instant_cmp = Ordering(Instant:a, Instant:b) {
    if (a.clock != b.clock) { fail ETimeValue; }              // ValueFault.ClockMismatch
    if (a.ns < b.ns) { pass Ordering.Less; }
    if (a.ns > b.ns) { pass Ordering.Greater; }
    pass Ordering.Equal;
};

#[derive(Eq, Ord, Clone, Debug, Copy)]
pub struct:Timestamp = { sealed int64:secs; sealed uint32:nanos; };

// `ensures answer.secs == secs && (answer.nanos => int64) == nanos`
// `prove((answer.nanos => int64) < NTIME_NANOS_PER_SEC)` -- `VERIFICATION.md`
// P-4, the invariant to prove first; a comment until the verified build (P-1b),
// and stood in for by `tests/unit/timestamp_construct.npk`.
pub func:timestamp_of = Timestamp(int64:secs, int64:nanos) {
    if (secs < NTIME_SECS_MIN)        { fail ETimeValue; }   // ValueFault.YearRange
    if (secs > NTIME_SECS_MAX)        { fail ETimeValue; }   // ValueFault.YearRange
    if (nanos < 0i64)                 { fail ETimeValue; }   // ValueFault.NanoRange
    if (nanos >= NTIME_NANOS_PER_SEC) { fail ETimeValue; }   // ValueFault.NanoRange
    pass Timestamp{ secs: secs, nanos: nanos =>! uint32 };
};
```

# 0.2.0 — `Instant`: the type, the clock tag, `instant_since`, and the refusals — PLANNED

> **Scope:** cycle 0.2's opening subcycle. `src/span/` stops being a
> placeholder: `Instant`, a reading of one of two clocks, and the four things a
> caller may do with readings — build one, subtract two of the same clock, add
> a `Duration`, compare two of the same clock. **The cycle README's 0.2.0 row
> ends with "a timeout cannot be written against a wall clock"**, and this plan
> makes that true the only way the language allows: there is no conversion
> between `Instant` and anything else, a consumer cannot build or edit an
> `Instant` by hand (the fields are sealed), and a probe asserts both refusals.
>
> **What it is not:** `Timestamp` (0.2.1), the conversions (0.2.2), the
> `Duration` constructors `ntime` adds (0.2.3), or the clocks themselves —
> `host_now_instant` and `host_now_boot` are cycle 0.3's, and they will build
> their answers through this plan's constructor. **Nor the re-pin**: if the
> workbench board has moved the toolchain past `c970483` before this runs, the
> adoption subcycle the orchestrator places runs first (the cycle README's
> "The adoption, when the pin moves"), and §1 is re-measured at the new pin
> before anything here changes.
>
> **Found at planning — each is a decision below, or a step:**
>
> 1. **The specifications disagree about what an `Instant` is.** `TIME_MODEL.md`
>    §2 declares `{ int64:ns; }` — *"a reading of `CLOCK_MONOTONIC`"* — and
>    M-4 gives `instant_since` as `Duration(…)`, never failing; `HOST.md` H-6
>    and TM-010's corollary (TM-010.1) give it a clock field and make
>    `instant_since` refuse a pair from two clocks. They cannot both be built.
>    PD-53 settles the type and PD-54 the operations, amending M-2, M-4 and H-6.
> 2. **The S-6 arm generator qualifies an identity by the module whose `fail`
>    site raises it, and the compiler by the module that declares it.** `span`
>    raises `cal`'s `ETimeValue`; `NITPICK-REACH-003` names `cal.ETimeValue`
>    and `arms.compute_bill` adds a `span.ETimeValue` that does not exist — so
>    the moment `span` has a body, `check_failsafe_arms` goes red for a defect
>    in the generator (§1.6). Latent until now: no module has raised an
>    identity it imports. PD-55 and step 1 fix the generator first.
> 3. **`BUILD.md` B-17 has no arrow from `host` to `span`**, and cycle 0.3's
>    `host_now_instant` returns an `Instant`. Not this subcycle's to change —
>    `host` is a placeholder until 0.3 — but it is why `instant_of` is public
>    (PD-54), and §7 hands it to 0.3's opening.
>
> **Written 2026-09-26 by cycle 0.1's close** (the second half of 0.1.5, stream

### 1.2 The candidate module compiles — and two spellings it needed

The module in §4.2, compiled as a root: **`npkc` exit 0**, the `.ll` written.
The first draft was refused, and each refusal is a rule the worker would meet:

| Draft | Verdict | So |
|---|---|---|
| `#[derive(Eq, Clone, Debug)]` on `Instant`, none on the enum | `NITPICK-TYPE-019` ×3 — *"`InstantClock` has no method `eq`"* (and `clone`, `debug`) | a derive reaches each field's own impl: the enum derives the same three |
| `pass duration_ns(…)` inside a fallible function | `NITPICK-TYPE-007` — *"expected `Duration`, found `Result<Duration>`"* | a `never fails` callee is called `raw` from a fallible body |

`later.clock != earlier.clock` compiles: `!=` on a payload-free enum is
accepted.

### 1.3 What a consumer can do with it — both legs

`m2_use`: two readings of one clock built by `instant_of`, `instant_since`
between them (3 500 ns), `instant_add` of that `Duration` to the earlier one,
`instant_cmp` of the sum with the later one (`Equal`), the clock read through
the sealed field, and the two refusals — `instant_since` and `instant_cmp` of a
`Boottime` reading against a `Monotonic` one each `is_error`. **Exit 0 at -O0
and after `opt -O2`.**

### 1.4 What a consumer cannot do — the refusals

| Program | Verdict |
|---|---|
| `m4_literal` — `Instant{ ns: 1000i64, clock: InstantClock.Monotonic }` in a consumer | **`NITPICK-TYPE-079`**, once per field, each with a note at the field's declaration |
| `m8_write` — `a.ns = 5i64;` on an `Instant` from `instant_of` | **`NITPICK-TYPE-079`** |
| `m5_convert` — `instant_to_timestamp(a)` | **`NITPICK-RESOLVE-002`** — *"cannot find `instant_to_timestamp` in this scope"* |

So the sealed fields make a hand-built or hand-edited `Instant` a refusal, and
the missing conversion is a refusal by name. **The stronger conversion
refusal — an `Instant` passed where a `Timestamp` is taken — needs
`Timestamp`, so it is 0.2.1's** (its checklist item, added by this plan's
step 5).

### 1.7 The specifications, read against each other

- `TIME_MODEL.md` M-2: `pub struct:Instant = { int64:ns; };`, *"a reading of
  `CLOCK_MONOTONIC`"*. `HOST.md` H-6: `pub struct:Instant = { int64:ns;
  uint8:clock; };`, *"clock: 0 monotonic, 1 boottime"*, and `instant_since`
  refuses a pair from two clocks. TM-010's corollary (TM-010.1) says the same

- M-4: `instant_since = Duration(Instant:later, Instant:earlier); // never
  fails*` — it cannot both never fail and refuse (TM-010.1). And

- The cycle README asks O-X3: *"`instant_clock(i)` read-only accessor, or

  which is the read-only exposure itself.
- The runtime's comment the README asks to be quoted is in
  `runtime/npkrt.ll` at `c970483`, the block headed *"the monotonic clock

  definition: *"CLOCK_MONOTONIC nanoseconds since an arbitrary epoch -- the
  deadline substrate's one clock. Wall clocks are excluded from the deadline
  path: NTP steps them, and a deadline that moves with the wall silently voids
  D-056's containment."* Read it with `git show c970483:runtime/npkrt.ll` and
  quote it from there, not from this file.

## 2. The decisions, and what chose each

| Label | Decision | Why this and not the alternative |
|---|---|---|
| **PD-53** | `Instant` is `{ sealed int64:ns; sealed InstantClock:clock; }`, and `InstantClock` is an enum, `{ Monotonic; Boottime; }`, each `#[derive(Eq, Clone, Debug)]`, neither `Ord`. Amends `TIME_MODEL.md` M-2 and `HOST.md` H-6 | **Sealed**, so a consumer cannot build an `Instant` from a number or edit one (`TYPE-079`, §1.4) — the type-level half of "a timeout cannot be written against a wall clock" — where M-2's bare field would let `Instant{ ns: wall_clock_ns }` compile. **An enum and not H-6's `uint8`**: a `uint8` holds 254 values that are no clock, and S-15c is this library's lesson that a tag outside an enum is a silent wrong answer. **No `Ord`**: a derived order compares readings of two clocks as though they were one — `instant_cmp` is the comparison, and it refuses. Declined: M-2 as written (no clock, and TM-010.1 unbuildable); H-6's `uint8` |
| **PD-54** | The operations: `instant_of(ns, clock)` — `never fails`, public, the one constructor; `instant_since(later, earlier)` — FALLIBLE, `ETimeValue` for two clocks; `instant_add(t, d)` — `never fails`, overflow traps; `instant_cmp(a, b)` — FALLIBLE, `ETimeValue` for two clocks. The refusal's detail is `ValueFault.ClockMismatch`, appended to `cal`'s enum. **O-X3 settled: the clock is the sealed field, read anywhere; there is no `instant_clock` function.** Amends M-4 | **`instant_of` is public** because cycle 0.3's `host` must build readings (§7), and a module may not write another's sealed field; a caller who hands it a wall-clock reading has opted out, stated as C-8b states it for `CivilDate`. **Fallible where a pair can be two clocks** — TM-010.1 asks it of `instant_since`, and the same argument covers `instant_cmp`. **`instant_add` traps** on overflow, as `TIME_MODEL.md` §8's table has said since cycle 0.0: a reading 292 years past boot. **`ClockMismatch` in `cal`'s `ValueFault`** because `ETimeValue`'s detail enum IS `ValueFault` (S-3); how it is handed back stays O-X8's. **No accessor function**: one public name fewer, and a sealed field already is read-only exposure. Declined: `instant_since` `never fails` with a trap for two clocks — a stop where the caller can answer; an `instant_clock` function beside the readable field |
| **PD-55** | The S-6 generator qualifies an identity by the module that DECLARES it: for a `fail X` in module M, M.X if M declares X, else the one module in the imported subgraph that does; two or none is a problem the check reports, never a guess. A fourth calibration specimen, `probe11_relay_lib.npk`, raises an identity it imports | §1.6: the compiler's REACH-003 is the oracle (S-6b) and it names the declaring module; the generator named the site's. Found by this plan, latent until `span` raises `cal`'s identity. **Before step 2**, or `check_failsafe_arms` is red for the generator's reason. Declined: reading the qualification out of REACH-003 itself — S-6b's point is that the source computation is the thing under test |
| **PD-56** | The refusals are two probes, dispatched by their own headers (`BUILD.md` B-4c): `probe20_instant_literal_refused.npk` (`TYPE-079`) and `probe20b_instant_conversion_refused.npk` (`RESOLVE-002`). Not a `check`-stage entry | Every refusal the library asserts is a probe of this shape — `probe15`, `probe16` … `probe16i`, `probe19` — the rule `tests/probe/README.md` states since cycle 0.1's close (a probe about the language's verdict on the library imports the module it asks about). A `check` entry would put one kind of file in two directories. Declined: `tests/rejection/` and its first `[[test]]` entry — worth it the day a refusal is not a probe's kind |

## 4. The code

### 4.1 What the module may and may not do

Imports `cal` for `ETimeValue` and nothing else (B-17: `span` → `cal`, `core`).
Declares no `error:` — `check_error_budget` fails `span.ETimeValue` since

### 4.2 `src/span/span.npk` — the code, measured in §1

```nitpick
mod:span;

use "../cal/cal.npk".ETimeValue;

#[derive(Eq, Clone, Debug)]
pub enum:InstantClock = { Monotonic; Boottime; };

#[derive(Eq, Clone, Debug)]
pub struct:Instant = { sealed int64:ns; sealed InstantClock:clock; };

pub func:instant_of = Instant(int64:ns, InstantClock:clock) never fails {
    pass Instant{ ns: ns, clock: clock };
};

pub func:instant_since = Duration(Instant:later, Instant:earlier) {
    if (later.clock != earlier.clock) { fail ETimeValue; }   // ValueFault.ClockMismatch
    pass raw duration_ns(later.ns - earlier.ns);
};

pub func:instant_add = Instant(Instant:t, Duration:d) never fails {
    pass Instant{ ns: t.ns + d.ns, clock: t.clock };
};

pub func:instant_cmp = Ordering(Instant:a, Instant:b) {
    if (a.clock != b.clock) { fail ETimeValue; }              // ValueFault.ClockMismatch
    if (a.ns < b.ns) { pass Ordering.Less; }
    if (a.ns > b.ns) { pass Ordering.Greater; }
    pass Ordering.Equal;
};
```

A first draft also held an `instant_clock` accessor; PD-54 drops it, and §1
was measured again on the text above — extracted from this file — without it. The header comments are the worker's to write, in
this repository's voice, from §1 and §2.

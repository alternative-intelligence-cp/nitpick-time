```python
#!/usr/bin/env python3
"""0.1.4's text, applied from THIS PLAN rather than transcribed from it
(`0.1.4.md` §0) -- 0.1.3's `apply.py`, pointed at this file. Every block the
worker applies is a fenced block in the plan headed by one marker line:

    <!-- apply GROUP: new PATH -->   the block is a new file; PATH must not exist
    <!-- apply GROUP: old PATH -->   the block must occur EXACTLY ONCE in PATH ...
    <!-- apply GROUP: to PATH -->    ... and the next block replaces it
    <!-- script: NAME -->            the block is a script, written to $W/NAME

`python3 apply.py GROUP` applies one group's blocks in document order and stops
at the first that does not apply, having written nothing for it;
`python3 apply.py scripts` writes every script. So what runs is the plan's own
text, byte for byte."""
import os, re, sys

REPO, W = os.environ["REPO"], os.environ["W"]
PLAN = os.environ.get("PLAN", os.path.join(REPO, "meta/roadmap/0.1/0.1.4.md"))
FENCE = r"\n(?P<fence>`{3,})[a-z]*\n(?P<body>.*?)\n(?P=fence)\n"
EDIT = re.compile(r"^<!-- apply (\w+): (new|old|to) (\S+) -->" + FENCE, re.S | re.M)
SCRIPT = re.compile(r"^<!-- script: (\S+) -->" + FENCE, re.S | re.M)
text = open(PLAN, encoding="utf-8").read()
want = sys.argv[1]
done = 0
if want == "scripts":
    for m in SCRIPT.finditer(text):
        body = m.group("body") + "\n"
        open(os.path.join(W, m.group(1)), "w", encoding="utf-8").write(body)
        print("  script %-26s %4d lines" % (m.group(1), body.count("\n")))
        done += 1
    print("scripts written: %d" % done)
    sys.exit(0 if done else 1)
pending = None
for m in EDIT.finditer(text):
    grp, kind, path, body = m.group(1), m.group(2), m.group(3), m.group("body") + "\n"
    if grp != want:
        continue
    full = os.path.join(REPO, path)
    if kind == "new":
        if os.path.exists(full):
            sys.exit("STOP: %s already exists; `new` writes only a file that does not" % path)
        os.makedirs(os.path.dirname(full), exist_ok=True)
        open(full, "w", encoding="utf-8").write(body)
        print("  new    %-44s %4d lines" % (path, body.count("\n")))
        done += 1
    elif kind == "old":
        if pending is not None:
            sys.exit("STOP: an `old %s` with no `to` after it" % pending[0])
        pending = (path, body)
    else:
        if pending is None or pending[0] != path:
            sys.exit("STOP: a `to %s` with no `old` for the same file before it" % path)
        cur = open(full, encoding="utf-8").read()
        n = cur.count(pending[1])
        if n != 1:
            sys.exit("STOP: in %s the old text occurs %d times, not once:\n%s"
                     % (path, n, pending[1][:300]))
        open(full, "w", encoding="utf-8").write(cur.replace(pending[1], body))
        print("  edit   %-44s -%d +%d lines" % (path, pending[1].count("\n"), body.count("\n")))
        pending = None
        done += 1
if pending is not None:
    sys.exit("STOP: an `old %s` with no `to` after it" % pending[0])
print("group %s: %d block(s) applied" % (want, done))
sys.exit(0 if done else 1)
```

## 2. The design, and what was measured to choose it

Every choice below has a draft decision in §14 with the alternatives it

### 2.1 Exhaustive, not sampled (PD-30)

C-18 and V-6 were written at cycle 0.0 as *"a few hundred thousand"* rows,
sampled — a guess about cost made before anything was measured. Measured at
planning at `c3bdae2`, with rows written out as a `fixed` table of nine
`int64` fields each (`.internal/p014/rows/`, the planner's scratch):

| Rows | Source | `npkc` once | `npkc` peak | `.ll` |
|---|---|---|---|---|
| 29 935 (every 122nd day) | 3.6 MB | 4.9 s | 87 MB | 3.3 MB |
| 98 705 (every 37th day) | 11.8 MB | 15.4 s | 231 MB | 10.6 MB |
| **280 928 (every 13th day — "a few hundred thousand")** | **33.7 MB** | **44.1 s** | **717 MB** | 30.1 MB |
| all 3 652 059, extrapolated | ≈ 440 MB | ≈ 570 s | ≈ 9 GB | — |
| **the chosen corpus: 9 999 digests** | **1.0 MB** | **0.95 s** | **20 MB** | 0.97 MB |

The harness compiles the corpus at least twice a run — the `parse` stage roots
it, and the member's build reaches it — so the sampled corpus alone would add
about 90 s to a full run that takes 100 s today, three times §8's whole
budget for the `sweep` stage.

**And a sample misses what falls between its rows.** 400 Gregorian years are
exactly 146 097 days, which is 20 871 weeks, so every February 29th of a
400-multiple year falls on the same weekday — a Tuesday. A sample taken every
seventh day meets all 24 of them in years 1 … 9999 or none of them, and one
taken on Mondays meets none: modelled exactly in §7's second table — the
member's own nine fields, folded on every seventh day only — it exits 0 with
its full count on a leap rule that drops those 24 days, where the chosen member
exits 15. A random sample of 300 000 days misses all 24 with probability
(1 − 300 000 / 3 652 059)²⁴ ≈ 0.13 — computed, not measured.

**So the agreement is checked over its whole domain**, which is what TM-026
asks wherever that is possible, and it stays a supplement rather than the gate
for TM-026's own reason: it trusts somebody else's library.

### 2.2 The digest, and what a failure prints (PD-31)

One row per year: `year`, `first` (the day number of its 1 January), `days`
(365 or 366) and `digest`. The digest folds nine fields of every day of the
year, in date order and in this order within a day:

| # | Field | Python — `tools/gen_civil_oracle.py` | `src/cal/` — the member |
|---|---|---|---|
| 1–3 | year, month, day | `date.fromordinal(o)` | the `CivilDate` `days_to_date(n)` returns |
| 4 | the day number | `o − date(1970, 1, 1).toordinal()` | `date_to_days` of that date |
| 5 | the weekday, Monday = 1 | `isoweekday()` | `weekday_number(weekday(…))` |
| 6–8 | the ISO week date | `isocalendar()` | `iso_week_year`, `iso_week_number`, `iso_weekday` |
| 9 | the day of the year | `timetuple().tm_yday` | `day_of_year` |

The fold is h ← (h XOR v) × 1099511628211 modulo 2⁶⁴ per field value v, from
h = 0 at each year's first day — the FNV-1a step applied to whole 64-bit
values rather than bytes. **The multiplier is odd, so each step is a bijection
of h for a fixed v, and one wrong value anywhere in a year always changes that
year's digest**; several could in principle cancel, with a chance of about
2⁻⁶⁴ for values not chosen to. In the member it is `(h ^ v) *% 1099511628211i64`
— `^` and the compiler's wrapping `*%` (D-312) on `int64` are exactly the
two's-complement operations the generator computes, and neither can trap or
arm anything. The digest is stored as a signed `int64` literal; −2⁶³, which has
no negated-literal spelling, never occurs, and the generator refuses it rather
than writing it wrong.

**A digest is opaque, so a failure prints the evidence.** Exit 14 — a year
that disagrees — first prints the member's nine fields for every day of that
year, one line a day; `python3 tools/gen_civil_oracle.py --year Y` prints
Python's in the same format, and `diff` names the day and the field. §7's
third table drives it: a weekday one day late differs from Python in fields
5 … 8 on all 365 days of year 1; a day of the year counted from zero in field 9
alone; and **a wrong CORPUS differs in nothing** — the library's rows equal
Python's, which is how a reader tells a wrong corpus from a wrong library
without a debugger.

### 2.3 The corpus is a module the member imports (PD-32)

`tests/fixtures/civil/civil_oracle.npk` declares `OracleYear`, `ORACLE_YEARS`
and `ORACLE`, and nothing else: no `main`, no function, no arithmetic. So:

- **it costs the member no arm** — the member's bill is `cal`'s eleven,
  measured (§2.7);
- **the harness treats it as the three probe support modules are treated**: a
  `.npk` under `tests/` with no marker is a failure unless it is named in
  `harness/run.py`'s `EXPECT_EXEMPT`, so it is named there, at the verdict
  `none` (no `main`), re-derived on every run (TM-137);
- **no `[[test]]` entry names `tests/fixtures/`**, and the `fixture` stage —
  the compiler's word for a PROGRAM built and handed to another by path — is
  not what this is: `BUILD.md` §3's row and `tests/README.md`'s both said
  `tests/fixtures/` belonged to it, and both are corrected (§10);
- **the `parse` stage roots it once**, like every `.npk` in the tree: 0.95 s
  and 20 MB, measured;
- **it owns nothing** — every field is an `int64` — so `SAFETY.md` S-19b and
  the move-out-of-`fixed` defect cannot reach it, and `check_no_owning_fields`,
  which reads `src/`, has nothing to say about it.

**The row type is imported by name beside the table** — `use
"../../fixtures/civil/civil_oracle.npk".OracleYear;` — because of §3's defect:
without it the member is refused `NITPICK-TYPE-001` at the corpus's own line,
and with it, a struct of the same name declared in the member is refused
`NITPICK-RESOLVE-001`, so the silent form cannot happen to this file.

### 2.4 What the member checks, and what it does not (PD-33)

**Per year, before its days:** the row's `year` is its position (exit 13, a
belt on the corpus's alignment); `is_leap_year`'s length of the year is the
row's `days` (15); `civil_date(Y, 1, 1)` is accepted (11) and its
`date_to_days` is the row's `first` (12). **Per day:** `days_to_date` accepts
every day number of the year (10), and the nine fields fold to the row's
digest (14).

**The length check is not decoration** — §7's second table measures the member
without it on a leap rule that makes every century year leap: `civil_date`
then accepts 1900-02-29, but `days_to_date` never produces it, so a walk over
day numbers folds exactly Python's fields and passes with the full count,
where the member exits 15 at year 100.

**It does not call `ordinal_to_date` or `iso_week_to_date`.** Given the
forward agreement this member proves, the reverse agreeing with Python is
V-4b's two members' result — each hands its reverse the walk's week or
ordinal date, which equals the forward function's and so Python's, for every
date of the range. Measured at planning, handing both reverses each day's
values takes the member from **3.4 s to 8.2 s at -O0**, which would take the
`sweep` stage from about 22 s to about 27 s of §8's 30 s, for no evidence it
lacks. **Nor does it fold the loop's own day number**: that number is Python's
(it walks the corpus's `first` … `first + days − 1`), so folding it would
compare Python with Python in that field; the member folds `date_to_days` of
the date `days_to_date` returned.

### 2.5 The corpus is regenerated, not edited (PD-34)

`tools/README.md` says everything a generator emits is committed as source and
checked by regeneration, and `TESTING.md` V-1a lists `check_tables_regenerate`
as pending until cycle 0.5 because *"what is missing is a generator and a
committed table"* — which stops being true at this subcycle's commit. **It
stays pending, and its reason is restated rather than left false**:
regenerating the corpus takes **10.7 s of CPython** (measured, twice, the two
outputs byte-identical), a tenth of a full run, for a file that changes only
when its generator does. So the subcycle that changes the generator
regenerates the corpus and `cmp`s it — step 10 here — and the corpus joins
`check_tables_regenerate` when that goes live at 0.5.3, whose checklist gains
the item (§10). The generator writes nothing that varies: no clock, no
dictionary order, no environment, and **not the interpreter's version** — that
is `CURRENCY.md`'s, so the file is a function of the generator and of
`datetime`'s answers.

<!-- script: arms.py -->

## 3. A compiler defect, found at planning — a `fixed` binding's type resolves in the importer's scope

**Found writing the member's first draft**, which imported the corpus's table
by name and not its row type: `npkc` refused it with `NITPICK-TYPE-001 …
civil_oracle.npk:8:11: there is no type named OracleYear` — reported at the
CORPUS's own declaration, which compiles alone. The compiler's **D-137**
(*"A declaration's annotations resolve in its HOME scope"*) says every type
annotation of a declaration resolves in the module that declared it, "never in
the scope of whatever module happens to be asking", and its own text names the
danger: *"under a name collision it would not have erred at all: it would have
silently bound the caller's same-named type."* A `fixed` binding's type is an
annotation D-137 does not list, and the collision is exactly what happens.

**The reproduction** is `importscope.py`: one module, `rows.npk`, declaring a
`Row`, a table `ROWS` of two of them, a scalar `ONE` and a function `mk`
returning one; and seven importers, each reading row 1's `x` — which is 3 —
and exiting 10 if it reads anything else. Run by the planner at all six pins
this repository has kept, both legs, each older pin compiling its importers
with the `(StackExhausted)` and `(MachineFault)` arms removed and nothing else
changed (0.1.3b's rule):

**What it says, case by case.** A table imported without its type is refused
at the declaring module's line (case 1) — loud. Imported beside a struct of
the same name, the table **takes the importer's layout**: it compiles and
reads row 1's `y` as its `x` (case 2), and with the importer's struct 8 bytes
wider the index strides 24 bytes over 16-byte rows (case 3) — the IR indexes
`@"npk.rows.ROWS"`, a `[2 x %"npk.rows.Row"]` of 32 bytes, as
`[2 x %"npk.case3_wider_same_name.Row"]`, so row 1 spans bytes 24 to 48 and
its last two fields lie past the table's end. **A fixed SCALAR does the same
(case 6)**, so it is the `fixed` binding's annotation, not the array. **A
function returning the type does not (case 7)**: D-137 covers signatures, and
they resolve at home. **The two that make it safe are the control and the
refusal**: imported with its type by name, the table reads correctly (case 4),
and with its type imported by name a same-named struct in the importer is
refused `NITPICK-RESOLVE-001` (case 5) — which is why the member imports
`OracleYear` by name. **Not a regression**: every verdict is the same at all
six pins.

**Its extent here, swept**: `git grep` over the six work repositories' tracked

`defect/big_fixed_array_cost` — and every one declares and reads its table in

## 4. The corpus, derived a second way and diffed against the tree

**0.1.1's lesson, applied to data rather than code**: a test's asserted value
and a specification's stated value are two lists nobody diffs — and a corpus
is a list of asserted values. So the corpus is recomputed by a method that
shares no code with `datetime` anywhere in the domain, and then compared with
every place the tree states the same facts. **And 0.1.2's**: a second method
that equals the first on part of its domain is one method there — so the count
reads no `datetime` at all, rather than `datetime` shifted.

- **P — the corpus**: Python's `datetime`, by the generator (§5).
- **C — a count**: C-3's leap rule for each year's length, lengths summed from
  1970-01-01 = 0 for each year's first day, the month table for month and day,
  the count modulo 7 from 1970-01-01's Thursday for the weekday, and ISO 8601's
  **Thursday** rule — the year and week of each date's Thursday — for the week
  date, where `src/cal/` uses the Monday on or before 4 January (TM-172); and
  the corpus header's fold, re-implemented from the header's words.

`crosscheck.py` diffs C against: every row of the corpus and `ORACLE_YEARS`;
the member's `sweep-count`; every row of `tests/unit/day_number_vectors.npk`
and of `tests/unit/derived_field_vectors.npk` whose year Python covers; and
the range's last day as `CALENDAR.md` §2 and `src/core/limits.npk` state it.

<!-- script: crosscheck.py -->
```python
#!/usr/bin/env python3
"""0.1.4's corpus, derived a SECOND way and diffed against every place the
tree states the same facts (`0.1.4.md` §4). TM-161's lesson: a test's value and
a specification's value are two lists nobody diffs.

  C -- a COUNT, and no `datetime` anywhere in this file: each year's length by
       C-3's leap rule, each year's first day number by summing lengths from
       1970-01-01 = 0, each date's month and day from the month table, its
       weekday from the count (1970-01-01 is a Thursday), and its ISO week date
       by ISO 8601's THURSDAY rule -- the year and week of the week's Thursday.
       The generator reads Python's `datetime` (C code: `ord_to_ymd`,
       `iso_week1_monday`), so the two methods share no code anywhere in the
       domain, not merely on part of it.

It re-implements the corpus header's fold from that header's words, and then
diffs C against: every row of the corpus; `ORACLE_YEARS`; the member's
`sweep-count`; every row of `tests/unit/day_number_vectors.npk` and of
`tests/unit/derived_field_vectors.npk` whose year Python covers; `CALENDAR.md`
§2's maximum day number; and `src/core/limits.npk`'s `NTIME_DAY_MAX`.
Exit 0 only if every one agrees; `CORPUS=path` points it at another corpus,
which is how its control runs."""
import os, re, sys

REPO = os.environ["REPO"]
CORPUS = os.environ.get("CORPUS", os.path.join(REPO, "tests/fixtures/civil/civil_oracle.npk"))
MASK, PRIME = (1 << 64) - 1, 1099511628211
MDAYS = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]


def leap(y):
    return y % 4 == 0 and (y % 100 != 0 or y % 400 == 0)


def ylen(y):
    return 366 if leap(y) else 365


FIRST = {1970: 0}                    # the day number of each year's 1 January, by the count
for y in range(1971, 10001):
    FIRST[y] = FIRST[y - 1] + ylen(y - 1)
for y in range(1969, -1, -1):
    FIRST[y] = FIRST[y + 1] - ylen(y)


def year_of(n):                      # only ever asked about y - 1 ... y + 1
    for y in (n_hint[0] - 1, n_hint[0], n_hint[0] + 1):
        if FIRST[y] <= n < FIRST[y + 1]:
            return y
    raise AssertionError(n)


NUM = r"(0i64 - \d+i64|\d+i64)"
VECTORS = (("tests/unit/day_number_vectors.npk", 4, lambda f: (f[3],)),
           ("tests/unit/derived_field_vectors.npk", 7, lambda f: (f[4], f[8], f[5], f[6])))


def val(s):
    s = s.replace("i64", "")
    return -int(s.split("-")[1]) if "-" in s else int(s)


def vector_rows(rel, width):
    """Each row of a vector file as its integers, in file order."""
    src = open(os.path.join(REPO, rel), encoding="utf-8").read()
    pat = re.compile(r"^\s*r = raw row\(" + r",\s*".join([NUM] * width) + r",\s*(\d+)i32\);", re.M)
    return [[val(g) for g in m.groups()[:width]] for m in pat.finditer(src)]


WANT = {tuple(r[:3]) for rel, width, _ in VECTORS for r in vector_rows(rel, width)}
n_hint = [1]
DAY = {}                             # (y, m, d) -> the nine fields, for the vectors' dates only
rows, bad = [], 0
for y in range(1, 10000):
    n_hint[0] = y
    h, n, doy = 0, FIRST[y], 0
    for m in range(1, 13):
        for d in range(1, (29 if (m == 2 and leap(y)) else MDAYS[m - 1]) + 1):
            doy += 1
            wd = (n + 3) % 7 + 1     # Python's % is a floor: 1970-01-01, day 0, is Thursday = 4
            thu = n - wd + 4         # the Thursday of this date's Monday-to-Sunday week
            iy = year_of(thu)
            iw = (thu - FIRST[iy]) // 7 + 1
            f = (y, m, d, n, wd, iy, iw, wd, doy)
            for v in f:
                h = ((h ^ (v & MASK)) * PRIME) & MASK
            if (y, m, d) in WANT:
                DAY[(y, m, d)] = f
            n += 1
    assert doy == ylen(y) and n == FIRST[y + 1]
    rows.append((y, FIRST[y], ylen(y), h - (1 << 64) if h >> 63 else h))
total = sum(r[2] for r in rows)
last = FIRST[10000] - 1
print("C: %d years, %d days, first day %d, last day %d" % (len(rows), total, FIRST[1], last))

# 1. The corpus, row by row, and its count.
text = open(CORPUS, encoding="utf-8").read()
got = [tuple(int(g) for g in m) for m in re.findall(
    r"^    OracleYear\{ year: +(\d+)i64, first: +(-?\d+)i64, days: +(\d+)i64, digest: +(-?\d+)i64 \}",
    text, re.M)]
count = re.search(r"^pub fixed int64:ORACLE_YEARS = (\d+)i64;$", text, re.M)
if len(got) != len(rows) or not count or int(count.group(1)) != len(rows):
    print("  CORPUS    %d rows, ORACLE_YEARS %s; C has %d" % (len(got), count and count.group(1), len(rows)))
    bad += 1
for want, have in zip(rows, got):
    if want != have:
        bad += 1
        print("  CORPUS    year %d: the corpus says %s; C says %s" % (want[0], have[1:], want[1:]))
print("corpus: %d row(s) read, %d disagree(s) with C" % (len(got), bad))

# 2. The member's declared domain.
member = open(os.path.join(REPO, "tests/unit/sweep/every_oracle_date.npk"), encoding="utf-8").read()
sc = re.search(r"^// sweep-count: (\d+)$", member, re.M)
ok = bool(sc) and int(sc.group(1)) == total
bad += not ok
print("member: sweep-count %s; C counts %d days  %s" % (sc and sc.group(1), total, "AGREE" if ok else "DISAGREE"))

# 3. and 4. The two vector files, wherever the year is Python's.
for rel, width, pick in VECTORS:
    seen = mism = 0
    for vals in vector_rows(rel, width):
        y, mo, d = vals[:3]
        if not 1 <= y <= 9999:
            continue
        seen += 1
        if tuple(vals[3:]) != pick(DAY[(y, mo, d)]):
            mism += 1
            print("  VECTOR    %s: %04d-%02d-%02d states %s; C says %s"
                  % (rel, y, mo, d, tuple(vals[3:]), pick(DAY[(y, mo, d)])))
    bad += mism + (seen == 0)
    print("%s: %d row(s) in years 1 ... 9999, %d disagree(s) with C" % (rel, seen, mism))

# 5. The two statements of the last day.
cal = open(os.path.join(REPO, "meta/specs/CALENDAR.md"), encoding="utf-8").read()
lim = open(os.path.join(REPO, "src/core/limits.npk"), encoding="utf-8").read()
m1 = re.search(r"\| maximum day number \| `\+([0-9 ]+)` \|", cal)
m2 = re.search(r"NTIME_DAY_MAX = (\d+)i64;", lim)
stated = (m1 and int(m1.group(1).replace(" ", "")), m2 and int(m2.group(1)))
ok = stated == (last, last)
bad += not ok
print("the last day: CALENDAR.md §2 says %s, limits.npk says %s; C says %d  %s"
      % (stated[0], stated[1], last, "AGREE" if ok else "DISAGREE"))
print("disagreements: %d" % bad)
sys.exit(1 if bad else 0)
```

```python
                                                  for every day of year Y

WHAT IT WRITES. One row per year `datetime` covers -- `datetime.MINYEAR` to
`datetime.MAXYEAR`, 1 to 9999 -- holding the year, the day number of its
1 January (epoch 1970-01-01 = 0), its length in days, and a DIGEST: the fold
below over nine fields of every one of its days, in date order. Each field is
Python's own answer, read from `datetime` and never computed here:

    year, month, day               `date.fromordinal(o)`
    the day number                 `o - date(1970, 1, 1).toordinal()`
    the weekday, Monday = 1        `isoweekday()`
    the ISO week date's three      `isocalendar()`
    the day of the year            `timetuple().tm_yday`

`src/cal/`'s answers for every day of every year and must equal every row.

THE FOLD. From 0 at each year's first day, for each field value v in turn,
h = (h XOR v) * 1099511628211, both modulo 2**64, v in two's complement; the
digest is h read as a signed 64-bit integer. The multiplier is odd, so each
step is a bijection of h for a fixed v: one wrong value anywhere in a year
changes that year's digest, always. Several wrong values could in principle
cancel; for values that are not chosen to, the chance is about 2**-64.

WHY A DIGEST AND NOT THE ROWS. Every day of years 1 to 9999 is 3 652 059
rows of nine numbers; a digest per year is 9 999 rows and loses nothing a
year's comparison needs. Measured at cycle 0.1.4's planning, rows written out
as a `fixed` table cost about 120 bytes and 0.16 ms of `npkc` each: a few
hundred thousand of them is 33.7 MB and 44 s, and all of them would be about
440 MB. When a year disagrees, the member prints its own nine fields for every
day of that year, and `--year` prints Python's in the same format, so `diff`
names the day and the field.

nothing about the interpreter in the output -- so the file is a function of

import sys

PRIME = 1099511628211

//   digest  the fold below, over nine fields of every one of its days in date
//           order: year, month, day, the day number, `isoweekday()`, the three
//           of `isocalendar()`, and `timetuple().tm_yday`

// h = (h XOR v) * 1099511628211, both modulo 2**64, v in two's complement; the
// digest is h read as a signed 64-bit integer. The multiplier is odd, so one
// wrong value anywhere in a year changes that year's digest.
// `tests/unit/sweep/every_oracle_date.npk` computes the same fold from
// `src/cal/`'s answers and must equal every row.

// THE LIMIT, STATED RATHER THAN GLOSSED: Python covers years 1 ... 9999 only,
// so the negative half of the range, -9999 ... 0, has `CALENDAR.md` C-16's
// self-consistency and nothing else.

mod:civil_oracle;

pub struct:OracleYear = { int64:year; int64:first; int64:days; int64:digest; };

pub fixed int64:ORACLE_YEARS = {count}i64;

pub fixed OracleYear[{count}]:ORACLE = [
"""


def fields(dt):
    """Python's nine answers for one day, in the fold's order."""
    iy, iw, iwd = dt.isocalendar()
    return (dt.year, dt.month, dt.day, dt.toordinal() - EPOCH,
            dt.isoweekday(), iy, iw, iwd, dt.timetuple().tm_yday)


def year_row(y):
    """(year, first, days, digest) for one year."""
    lo = datetime.date(y, 1, 1).toordinal()
    hi = datetime.date(y, 12, 31).toordinal()
    h = 0
    for o in range(lo, hi + 1):
        for v in fields(datetime.date.fromordinal(o)):
            h = ((h ^ (v & MASK)) * PRIME) & MASK
    # -2**63 has no negated-literal spelling; it never occurs, and is refused
    # here rather than written wrong if it ever did.
    assert h != 1 << 63, "year %d folds to -2**63" % y
    return y, lo - EPOCH, hi - lo + 1, (h - (1 << 64) if h >> 63 else h)


def write(path):
    assert (datetime.MINYEAR, datetime.MAXYEAR) == (1, 9999), \
        "this corpus and its member assume datetime's range is 1 ... 9999"
    years = range(datetime.MINYEAR, datetime.MAXYEAR + 1)
    rows = ["    OracleYear{ year: %4di64, first: %8di64, days: %3di64, digest: %20di64 }"
            % year_row(y) for y in years]
    text = HEADER.replace("{count}", str(len(rows))) + ",\n".join(rows) + "\n];\n"
    with open(path, "w", encoding="utf-8", newline="\n") as fh:
        fh.write(text)
    print("wrote %s: %d years, %d bytes" % (path, len(rows), len(text.encode("utf-8"))))


def show(y):
    """Python's nine fields for every day of year y, one line per day, in the
    format the member prints for a year that disagrees."""
    lo = datetime.date(y, 1, 1).toordinal()
    hi = datetime.date(y, 12, 31).toordinal()
    for o in range(lo, hi + 1):
        print(" ".join(str(v) for v in fields(datetime.date.fromordinal(o))))


def main(argv):
    if len(argv) == 2 and argv[0] == "--year":
        show(int(argv[1]))
        return 0
    if len(argv) == 1 and not argv[0].startswith("-"):
        write(argv[0])
        return 0
    sys.stderr.write(__doc__)
    return 2


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

**PD-30 — the civil cross-oracle is exhaustive over Python's range: every date

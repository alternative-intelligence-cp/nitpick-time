## 3. The steps, and what each commit carries

**The instrument, then the double and its tests, then the mutants, then the documents, then the prose, then the
record.** Steps 1 … 4 each apply one patch, which `apply.py` STAGES, and each is committed at its block's end — exactly
the staged files, with the dispatch's `ATTRIBUTION` lines and the subject the step names. Step 0 changes nothing, and
block 2m commits nothing. This file's title is set `RUNNING (since <date>, <stream>)` after block 0a, uncommitted, and
lands with the record. Every commit: `check_refs` clean (each block runs it once its patch is staged); `git status
--short` read. **Nothing is pushed until step 6**: GitHub runs a push's head only, so the four work commits are read
in CI through the head's run, and each one's green is its block's full local run.

**The order is load-bearing.** The check before the double, so its plants are seen to fail before there is a double to
hold; the double and its tests together, since a test is how the double is read; the mutants over the committed double;
the documents before the prose, which states what they made true.

## 2. Decisions taken at planning

- **P-7 — one placeholder module per directory, and it parses.** An empty
  directory is invisible to the `parse` sweep, and the sweep is what stops the
  grammar being quietly made partial. Each is `src/<dir>/<dir>.npk` with
  `mod:<dir>;` and a header comment naming the specification section that will
  fill it and the cycle that will do it. They are replaced, not deleted.
- **P-8 — `src/lib.npk` re-exports deliberately, one line per public name.**
  `use` is not transitive (`MODULE_REFERENCE.md` §2.3), so the surface is a
  list a reviewer can read in one file. That is a feature and the reason the
  library has an umbrella at all.
- **P-9 — the consumer test imports by relative path** (`specs/BUILD.md` B-16)
  and carries a comment naming O-N1 as the reason, so the day dependency roots
  work, the thing to change is greppable.
- **P-10 — CI pins the compiler by commit**, not by branch. The compiler is
  moving through cycle 1.5; a library whose CI tracks its `main` is a library
  whose CI breaks for reasons that are not its own. Bumping the pin is a
  deliberate commit that runs the full suite.
- **P-11 — the placeholder for `src/host/` carries the purity comment from
  day one.** It is the module every other file is forbidden to import
  (`BUILD.md` B-17), and the header saying so is what a reader meets before the
  rule is enforced by a check at 0.3.

## 3. Steps

1. **The module skeleton.** Six placeholder modules, `src/lib.npk`, and the
   layering comment in each header naming what it may import
   (`specs/BUILD.md` §6's diagram). Commit.
2. **The consumer.** `tests/conformance/import.npk`: `mod:import;`,
   `use "../../src/lib.npk".*;`, a `main` that exits 0, a `failsafe` with the
   system arms. It compiles against an empty surface, which is the point — it
   keeps compiling as the surface grows, and the day it does not, the surface
   changed incompatibly.
3. **`nitpick.toml`.** The first `[[test]]` entries: `probe` (stage `program`,
   `tests/probe`) and `conformance` (stage `compile`, kind `positive`).
4. **CI.** A workflow that: checks out `ntime`; checks out the compiler at the
   pinned commit; installs LLVM 20.1.2; builds the compiler; runs
   `harness/run.py` (a stub until 0.0.2, which still must exit 0). Runs on push
   and on pull request.
5. **`CLAUDE.md` and `CONTRIBUTING.md` reviewed.** Both were written at
   repository setup, before the probes ran. This step re-reads them against
   0.0.0's verdicts and extends the reserved-word list and the "four things
   that will surprise you" with whatever the probes actually cost.

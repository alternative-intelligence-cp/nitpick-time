# 0.0.3 — the harness, part 2 — PLANNED

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-18 — the exact-code rule from the start** (D-237, `BUILD.md` B-7). On the
  error channel the set of codes a rejection test reports must EQUAL the set
  its expectations name. The compiler ran the weaker subset rule for six cycles
  and found, when it tightened, that 17 of 131 files were reporting something
  nobody had asserted. Starting strict costs nothing; loosening later is
  impossible.
- **P-19 — a skipped stage prints a line saying it was skipped and why.**
  Silence is how a suite becomes green on a machine where it ran nothing — and
  for this library that failure has a specific shape, §3's case 7.
- **P-20 — the tree checks run on every full invocation**, including the ones
  that currently have nothing to check. `check_no_owning_fields` over an empty
  set is the right answer and is what makes the check exist on the day the
  first table type is written.
- **P-21 — `check_purity` and `check_host_isolation` are written now and
  dormant.** They go live at cycle 0.3 when `src/host/` exists. Writing them
  here means 0.3 *turns them on* rather than inventing them, which is the
  compiler's rule that instruments precede the constructs they guard.
- **P-22 — `--only` and `--quick` each print, twice, that a filtered run
  concludes nothing.** The compiler's phrasing, adopted whole.

## 2. The stages added

| Stage | Tool | Passes when |
|---|---|---|
| `parse` | the compiler's `tools/parse_check` | every `.npk` in the tree accepted with no diagnostic, each once |
| `accept` | the compiler's `tools/check` | accepted in silence |
| `check` | the compiler's `tools/check` | refused with **exactly** the expected codes |
| `golden` | the built program | its stdout matches the committed golden byte for byte |
| `sweep` | the built program | as `program`, but long; skipped by `--quick` **with a loud line** |

The three tools come from the compiler's tree, built once per run from the
pinned checkout.

## 3. The self-check — the seven cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one;
2. a `check` case expecting a code the compiler does not report;
3. a `check` case reporting a code no expectation names — the D-237 rule;
4. a `golden` case whose bytes differ by one byte;
5. a `parse` case that does not parse;
6. a generator whose output differs from the committed table by one line
   *(pending until 0.5)*;
7. **a `sweep` case that is silently skipped** — the harness must notice that
   the exhaustive test did not run and fail.

**Case 7 is this library's most important self-check case.** `ntime`'s
strongest claim is an exhaustive sweep (TM-026), and the most plausible way to
be green and wrong is for that sweep to quietly not have run.

**Rule:** the self-check runs **first** in every full invocation, and a pending
case prints as pending rather than passing.

## 2. The two functions, decided at planning

In `src/cal/cal.npk`, after `days_in_month` and before the constructors, with
`use "../core/limits.npk".NTIME_DAY_MIN;` and `….NTIME_DAY_MAX;` added to the
file's `use` block. **This is the text that compiled and passed at `c3bdae2`:**

```nitpick
pub func:date_to_days = int64(CivilDate:cd) never fails {
    int64:m = cd.month => int64;
    int64:d = cd.day => int64;
    int64:y = cd.year => int64;
    if (m <= 2i64) { y = y - 1i64; }
    int64:era = (is (y >= 0i64) : y : (y - 399i64)) / 400i64;
    int64:yoe = y - (era * 400i64);
    int64:mp = is (m > 2i64) : (m - 3i64) : (m + 9i64);
    int64:doy = (((153i64 * mp) + 2i64) / 5i64) + d - 1i64;
    int64:doe = (yoe * 365i64) + (yoe / 4i64) - (yoe / 100i64) + doy;
    pass (era * 146097i64) + doe - 719468i64;
};

pub func:days_to_date = CivilDate(int64:n) {
    if (n < NTIME_DAY_MIN) { fail ETimeValue; }   // ValueFault.YearRange
    if (n > NTIME_DAY_MAX) { fail ETimeValue; }   // ValueFault.YearRange
    int64:z = n + 719468i64;
    int64:era = (is (z >= 0i64) : z : (z - 146096i64)) / 146097i64;
    int64:doe = z - (era * 146097i64);
    int64:yoe = (doe - (doe / 1460i64) + (doe / 36524i64) - (doe / 146096i64)) / 365i64;
    int64:y = yoe + (era * 400i64);
    int64:doy = doe - ((365i64 * yoe) + (yoe / 4i64) - (yoe / 100i64));
    int64:mp = ((5i64 * doy) + 2i64) / 153i64;
    int64:d = doy - (((153i64 * mp) + 2i64) / 5i64) + 1i64;
    int64:m = is (mp < 10i64) : (mp + 3i64) : (mp - 9i64);
    if (m <= 2i64) { y = y + 1i64; }
    pass (relay civil_date(y, m, d));
};
```

**The decisions in that text, each with what it declined** (PD-13 records them):

- **`date_to_days` is `never fails` and TOTAL over every field value.** With
  `year` an `int32` and `month`/`day` `uint8`, widened by the CHECKED `=>`
  (C-12), `|era| ≤ 5.4 × 10⁶` and `|era × 146 097| ≤ 7.9 × 10¹¹`: nothing can
  overflow `int64`, and every divisor is a nonzero literal, so no path traps.
  After C-8c its argument can only have come from `civil_date` — the totality is
  C-8b's second bullet, kept because it is free and `wild` is still an opt-out.
  *Declined:* a fallible `date_to_days` re-checking validity — the seal already
  guarantees it, and a second copy of the check is a second place to disagree.
- **`days_to_date` checks its range FIRST, before `n + 719468`** (S-12: checked
  before the trap). At `int64` MAX that addition would trap `IntOverflow`; the
  refusal test (§4c) asserts the check comes first.
- **`days_to_date` builds through `relay civil_date(y, m, d)`**, not a struct
  literal. So `civil_date` stays the only builder in `src/` (C-8 inside `cal`),
  the `int64 → int32/uint8` narrowing is validate-then-narrow by construction
  (TM-105), and **an algorithm error becomes a refusal the 0.1.2 sweep sees**
  rather than a wrong date it might not. Cost: five compares and one
  `days_in_month` per call, inside the 1.23 s above. *Declined:* the literal —
  one line shorter and it moves the narrowing back into this function; a
  private `Ymd` struct returned to a wrapper — a second type for one caller.
- **The negative-year corrections are Hinnant's, as given** (C-10): `era`'s
  `y - 399` and `z - 146096`. `../0.1.0.md` §6 recorded that the leap rule did
  not need one and `era` does; the vectors −1, −4, −100, −400 and −401 (§4a)
  are that correction under test.
- **`is (c) : a : b`** is the ternary (CONTROL_REFERENCE §1.4), measured at
  `c3bdae2`; Hinnant's `(m <= 2)` added to an integer becomes an `if`.
- **The names**: the parameter is `cd` so it does not read as `CivilDateTime`'s
  field `date` (`date` itself is a legal name — 0.1.0 measured it); `mp`,
  `doy`, `doe`, `yoe` and `era` are Hinnant's own, so the transcription can be
  checked against the page line by line.
- **No loop, so no measure and no `DecreasesViolated`**: `cal`'s arm bill stays
  **11** — measured with this text. The module header says so, because the next
  function added here that loops will add the arm.
- **The header cites the source**: the page, its URL, the page's own date
  (2021-09-01) and the date read (2026-09-25), *"per `meta/research/CURRENCY.md`"*
  — and names the one deviation: Hinnant's `unsigned` intermediates are `int64`
  here (C-12), which makes the arithmetic total on inputs his `unsigned` would
  wrap.

## 3. C-11: every divisor a nonzero literal, and the check that says so

**After this subcycle `src/cal/cal.npk` divides by:** `%` 4, 100, 400
(`is_leap_year`) and 7 (`weekday_number_sunday_first`); `/` 400, 5, 4, 100
(`date_to_days`) and 146 097, 1 460, 36 524, 146 096, 365, 153, 5, 4, 100
(`days_to_date`). **C-11's own list — *"(4, 5, 100, 400, 146097)"* — names
`days_from_civil`'s divisors only**; PD-14 amends C-11 to state the rule and
point at the check rather than carry a list that the next function falsifies.

**`check_literal_divisors`**, a new LIVE tree check in `harness/checks.py`,
registered in `LIVE` beside `check_constants_named`:

- **Scope:** every `.npk` under `src/cal/` (C-11 is the calendar's rule;
  `SAFETY.md` S-16's library-wide rule admits a *proven* divisor, which a text
  check cannot see).
- **Reads code, never prose:** `code_lines` (comments and string bodies
  blanked), as `check_civil_literal` did.
- **An operator** is a `/` or a `%` that is not part of a wrapping operator:
  a `%` immediately preceded by `+`, `-` or `*` is `+%`/`-%`/`*%` (D-312) and
  is not a division. A compound `/=` or `%=` is a division.
- **Its right operand**, after optional whitespace and optional `(`, must match
  `[1-9][0-9]*(i|u)(8|16|32|64|128)\b` — a nonzero integer literal with its
  width suffix. Anything else is a finding naming the file, the line and the
  operand's text: *"divides by `m`, which is not a nonzero literal (C-11): the
  divide-by-zero trap is no longer unreachable by construction"*; a literal
  zero gets its own sentence.
- **Its headline states its denominator**:
  `N division(s) over M file(s) in src/cal/, every divisor a nonzero literal`,
  and an empty scope is a failure (V-1b), as `check_civil_literal` did it.
- **Commissioned** (TM-126) in `harness/selfcheck.py`'s tree-check plants, in
  the tuple form the others use: a violation
  `("src/cal/cal.npk", "mod:cal;\nfunc:f = int64(int64:y, int64:m) never fails { pass y / m; };\n")`
  against a control with `/ 400i64` in its place, expecting `"is not a nonzero
  literal"`; a second plant `% 0i64` against `% 4i64`, expecting `"literal
  zero"`; and a third whose control is the WRAPPING form `y +% 1i64` beside a
  real `/ 4i64` — the proof that `+%` is not read as a division. The self-check's
  planted count goes up by three; read it from the run.
- `../../specs/TESTING.md` §2 gains its row; `CLAUDE.md`'s check count is
  re-derived.

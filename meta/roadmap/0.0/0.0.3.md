# 0.0.3 — the harness, part 2 — DONE (2026-09-05)

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-18 — the exact-code rule from the start** (D-237, `BUILD.md` B-7). On the
  error channel the set of codes a rejection test reports must EQUAL the set
  its expectations name. The compiler ran the weaker subset rule for six cycles
  and found, when it tightened, that 17 of 131 files were reporting something
  nobody had asserted. Starting strict costs nothing; loosening later is
  impossible.
- **P-19 — a skipped stage prints a line saying it was skipped and why.**
  Silence is how a suite becomes green on a machine where it ran nothing — and
  for this library that failure has a specific shape, §3's case 7.
- **P-20 — the tree checks run on every full invocation**, including the ones
  that currently have nothing to check. `check_no_owning_fields` over an empty
  set is the right answer and is what makes the check exist on the day the
  first table type is written.
- **P-21 — `check_purity` and `check_host_isolation` are written now and
  dormant.** They go live at cycle 0.3 when `src/host/` exists. Writing them
  here means 0.3 *turns them on* rather than inventing them, which is the
  compiler's rule that instruments precede the constructs they guard.
- **P-22 — `--only` and `--quick` each print, twice, that a filtered run
  concludes nothing.** The compiler's phrasing, adopted whole.

## 3. The self-check — the seven cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one;
2. a `check` case expecting a code the compiler does not report;
3. a `check` case reporting a code no expectation names — the D-237 rule;
4. a `golden` case whose bytes differ by one byte;
5. a `parse` case that does not parse;
6. a generator whose output differs from the committed table by one line
   *(pending until 0.5)*;
7. **a `sweep` case that is silently skipped** — the harness must notice that
   the exhaustive test did not run and fail.

**Case 7 is this library's most important self-check case.** `ntime`'s
strongest claim is an exhaustive sweep (TM-026), and the most plausible way to
be green and wrong is for that sweep to quietly not have run.

**Rule:** the self-check runs **first** in every full invocation, and a pending
case prints as pending rather than passing.

### 2. What the work found

**1. The compiler's frontend tools are SOURCE, not binaries (TM-123).** Both
the cycle plan and `BUILD.md` §3 name `tools/parse_check` and `tools/check` as
the tools for three of this subcycle's stages, and describe them as *"built once
per run from the pinned checkout"*. Read at the pin: `tools/parse_check.npk` is
131 lines importing twenty of `src/frontend/`, and `tools/check.npk` imports the
whole driver pipeline. Building either is **building the compiler**, from a tree
that is ahead of our pin and moving — W-18 forbids it, and it would put an
unpinned parser behind a stage whose siblings are held to an exact LLVM patch
release. The stage asks `$NPKC` and reads the diagnostic's **code family**
instead.

**2. `npkc` exits 2 on an unknown argument, not 0 — and the first measurement
said 0.** The command was `npkc --help 2>&1 | head -30; echo "EXIT=$?"`, and
`$?` after a pipeline is `head`'s. Re-measured with a redirect and the status on
its own line: **exit 2**. Nothing depended on the wrong number, and it is
recorded because it happened *while reading the instruction not to do it*.

**3. `SAFETY.md` §2 carried a stale parenthetical about the pin.** It said
`NITPICK-REACH-003` is *"not in the pinned toolchain, so this constraint
stands"*. Measured: at `0dfddac`, `case1_no_failsafe.npk` **is** refused
REACH-003, exit 1, no `.ll` written. **The constraint stands anyway and now
says why**: a stage must not depend on which pin it runs against, and a rule
justified by "our compiler does not do this yet" evaporates the day it does —
taking the belt with it, at exactly the moment nobody is watching.

**4. `check_specs_current` found a live cross-repository citation on its first
run.** `0.0.0.md:1328` cites `S-23`, which this repository's `SAFETY.md` does
not declare — because it is **`nitpick-regex`'s** S-23, and the sentence says
so. Every library numbers its own `S-` rules, so the namespaces collide by
design. Exempted **by name with the reason** (V-1c) rather than filtered out by
a cleverer pattern that would also have hidden a real one.

**5. Two of the self-check's own fixtures were ineffective, and the self-check
is what caught both.** They are worth recording as a pair, because both are the
shape it exists to find:

- the `npkc` wrapper for case 8 renamed `@npk_failsafe` to
  `@npk_failsafe_DELETED_BY_SELFCHECK` — and `build_program`'s belt tests
  `text.count("\ndefine i32 @npk_failsafe")`, which **still matches the renamed
  symbol as a substring**. The fault was planted and the check sailed past. The
  rename now replaces the prefix;
- `invoke()` built the child environment with the wrapper in `$NPKC` and then
  called `subprocess.run` **without passing `env=`**. Case 8 therefore ran its
  *control* twice and reported that the harness had not caught its planted
  fault. It was right: nothing had been planted. That is TM-120's defect — a
  constructed environment that never reaches the process — arriving one level
  up, in the thing that tests the thing that has the rule.

**6. A check over source must not read prose, and this tree proves it twice.**
`src/host/host.npk`'s header contains `mono_now()` while explaining the purity
rule; `src/lib.npk`'s contains `host_now_utc` while showing the shape of a
re-export line. A `grep`-shaped `check_purity` or `check_host_isolation` would
fail this repository **on its own documentation** on its first run. Both checks
blank comments (string-aware, preserving line numbers) before scanning, and the
clean control in the self-check is a file where the banned form appears *in a
comment*.

**7. A numeric literal carries its type suffix, so `\b(\d+)\b` does not match
`86400i64`.** The first `check_constants_named` walked straight past
`selfcheck.py`'s planted constant. Caught by the plant, which is the argument
for planting.

**8. An exemption list is a statement about ONE tree.** `EXPECT_EXEMPT` names
three files under `tests/probe/support/`, and its both-directions diff (V-1c)
fired three times in *every* inner run against a scratch tree that legitimately
has none of them. Both exemption tables — that one and `CITATION_EXEMPT` — now
apply only when the tree being checked is this repository, and say so.

**9. `check_failsafe_arms` is not "0 of 0" today.** It generates and verifies
**six rows** — one per `src/` module — each owing the floor of four, every one
diffed against `NITPICK-REACH-003`'s own list. The plan expected an empty
denominator; the compiler's diagnostic made a real one available.

### 6. What is NOT proved, stated because a green run invites the opposite

- **Not that the library works.** There is none; `src/` is placeholders. Every
  tree check that reports `0` is reporting `0` over a small denominator, and the
  denominator is printed for exactly that reason.
- **Not purity of anything, yet.** `check_purity` is live, source-level and
  commissioned — over **six placeholder files containing no code**. What is
  proved is that the instrument works and fails correctly; 0.3 is where it has a
  real module to be right about.
- **Not that the S-6 table is right for `ntime`.** Its six rows are six
  placeholder modules owing the floor. What is proved is that the generator
  agrees with the compiler on three modules that genuinely differ — which is the
  part that would otherwise be discovered at 0.1.
- **Not that CI is green.** It has still never run; this repository pushes at a
  cycle's end and 0.0.3 does not push. The workflow's stale claim that the
  runner has no self-check was corrected in this commit, and the run step now
  asserts the **unqualified** `GREEN --` line so a later `--quick` cannot
  quietly weaken the badge.
- **Not that `--quick` skips anything today.** There is no `sweep` entry in the
  manifest, because `tests/unit/sweep/` is empty and an entry naming an empty
  directory is refused. `--quick`'s skip path is exercised only inside the
  self-check. The entry arrives at 0.1 with the civil sweep, and
  `nitpick.toml` now says so beside the four other stages that have no entry.

### 7. For the next subcycle

0.0.4 inherits a runner that has been shown able to fail, nine live tree checks,
and four stages with no members. Five things bear directly on it:

1. **Three checks are waiting for `src/core/` specifically**, and each will go
   from `0` to a real denominator the moment it lands: `check_raw_index` (the
   `.items[`/`.ptr[` owners are `vec.npk` and `bytes.npk`, which 0.0.4 writes),
   `check_constants_named` (`limits.npk` is where every named bound goes), and
   `check_no_owning_fields`. **They are already commissioned**, so a violation
   in the first draft of `Vec<T>` is a red run rather than a review comment.
2. **`check_constants_named`'s owner map says all four magic numbers belong to
   `cal`**, because `SAFETY.md` S-16 says *the calendar algorithms* divide by
   them. If 0.2 gives `span` its own nanosecond arithmetic, the right move is to
   amend S-16 **and** the map in one commit — the check's contract is that it
   fails when the tree and the document disagree, and the fix is whichever of
   the two is wrong.
3. **A `sweep` member needs `// sweep-count: N` and a `swept <N>` line**, and
   the program has to write it with `sys(1, 1, ptr, len)` — the prelude has no
   output function this library may use (`lib/nio.npk` is the compiler's `lib/`
   and B-10 excludes it). The shape is in `selfcheck.py`'s `WRITER` template.
4. **A `failsafe` in a fixture must NAME the module's own identity**; `(*)`
   counts for nothing (D-179). Every writer program in the self-check was
   refused `NITPICK-REACH-002` until the `(EW)` arm was added — the language's
   own rule, met in the harness's fixtures rather than in the library.
5. **The full run is 184 s and the self-check is 78 of them.** `--only` still
   runs the self-check and the parse stage in full, so the fast inner loop is
   about 120 s. If that becomes the constraint, the answer is the prelude cost
   (TM-117) and not the self-check.

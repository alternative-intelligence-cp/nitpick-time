```python
#!/usr/bin/env python3
"""0.1.3 (`0.1.3.md` §1.3): which year decides the ISO week of 1 January?
Python's `isocalendar()` over every year from 2 to 9998, the cases grouped by
the shape of the year that BEGINS -- C-14's wording -- and by the shape of the
year before it. A shape is (the weekday of 1 January, leap or common)."""
import datetime
from collections import defaultdict
def leap(y): return y % 4 == 0 and (y % 100 != 0 or y % 400 == 0)
DAYS = ["Mon","Tue","Wed","Thu","Fri","Sat","Sun"]
# Python covers 1..9999; shapes repeat every 400 years exactly (146097 days = 20871 weeks)
def shape(y): return (datetime.date(y,1,1).weekday(), leap(y))
# Does Jan 1's ISO triple depend only on Y's shape?
by_own = defaultdict(set); by_prev = defaultdict(set)
for y in range(2, 9999):
    iy, w, wd = datetime.date(y,1,1).isocalendar()
    rel = (iy - y, w, wd)
    by_own[shape(y)].add(rel)
    by_prev[shape(y-1)].add(rel)
print("Jan 1 ISO (year offset, week, weekday), indexed by THIS year's shape:")
for k in sorted(by_own): print("  %s %-6s -> %s" % (DAYS[k[0]], "leap" if k[1] else "common", sorted(by_own[k])))
print("ambiguous by own shape:", [ (DAYS[k[0]], k[1]) for k in by_own if len(by_own[k]) > 1])
print("ambiguous by PREVIOUS year's shape:", [ (DAYS[k[0]], k[1]) for k in by_prev if len(by_prev[k]) > 1])
# Dec 31 by own shape
dec = defaultdict(set)
for y in range(1, 9999):
    iy, w, wd = datetime.date(y,12,31).isocalendar()
    dec[shape(y)].add((iy - y, w, wd))
print("Dec 31 ambiguous by own shape:", [k for k in dec if len(dec[k]) > 1])
# weeks in year by shape
wk = defaultdict(set)
for y in range(1, 9999):
    wk[shape(y)].add(datetime.date(y,12,28).isocalendar()[1])
print("53-week shapes:", sorted((DAYS[k[0]], k[1]) for k in wk if 53 in wk[k]))
# distinct year shapes that occur in a 400-year cycle
print("shapes in 1..400:", len({shape(y) for y in range(1,401)}))
```

### 2.3 The weekday: one index, a belt, and a manufactured tag (PD-22)

C-13 is `(days + 3) mod 7` with a non-negative correction, Monday = 0. The
index has to become a `Weekday`, and **`intN => Enum` is impossible in both
spellings** (the compiler's TYPE_REFERENCE §9.3), so the choices were three:

- **`=>!`, which manufactures a tag** (the compiler's D-140) — the exact
  inverse of `weekday_number`'s `w =>! int32`, and the enum stays the one
  statement of C-7's order. But the compiler does not check it, and an index
  outside 0 … 6 — which is what the correction's absence gives, on six days in
  seven before 1969-12-29 — becomes a `Weekday` that is none of the seven.
  **Measured**, `$W/forge.npk` (below): a tag of −6 reads back as −5 through
  `weekday_number`, and an exhaustive seven-arm `pick` over it **matches none
  and falls through**, exit 0, both legs.
- **A `fixed Weekday[7]` table indexed by the index** — which would turn a bad
  index into an `OutOfBounds` trap. **Not spellable**: `$W/table.npk` is
  refused `NITPICK-TYPE-035` at `c3bdae2`; an enum variant is not a
  compile-time constant for a module-level initialiser.
- **A seven-arm `pick` on the index** — restates C-7's order a second time,
  and its catch-all turns a bad index into a VALID wrong weekday.

**Chosen: the first, with the index range-checked on the same path.** The
correction lives in one private function, `weekday_index`, which every weekday
computation calls — `weekday`, `iso_weekday`, and the ISO week's first Monday
— and after the correction it asserts `0 ≤ rem ≤ 6` with `#unreachable()`
(the compiler's CONTROL_REFERENCE §1.2.2: explicit, greppable, and it traps
through the floor's `Unreachable`). The correction makes the check dead code on
every input; **what the check buys is §7's row D1**: with the correction
deleted, every test that computes a pre-1970 weekday stops at exit 95 instead
of answering, where row D2 — correction AND check deleted, the 0.1.2 planner's
mutant exactly — shows the forged tags reaching the tests. S-15b already
requires a range check before every narrowing; **S-15c** (drafted in §10)
says what that check does when the value is the library's own and there is no
caller to answer: `#unreachable()`, not an `ETimeValue`.

**So the rider's known trap is closed twice**: by the rider's form (a count,
which D2 fails on the range's second day where *"advances by one, mod seven"*
passes all 7 304 483 steps — §7's second table) and by construction (D1).

```nitpick

//
// 0.1.3 (`0.1.3.md` §2.3): WHAT A MANUFACTURED TAG DOES. `intN =>! Enum` is
// permitted and unchecked (the compiler's D-140). In range it is exactly the
// variant; out of range it is a value that is NONE of the variants -- its tag
// read back is the number written, and an exhaustive `pick` over all seven

enum:Wd = { Mon; Tue; Wed; Thu; Fri; Sat; Sun; };

func:make = Wd(int64:k) never fails {
```

### 2.4 The ISO week: the Monday on or before 4 January (PD-23)

ISO 8601-1:2019's clause 3.1.1.23 defines week 1 as *"the week including the
first Thursday of that year"* ([`iso-8601-week-date.md`](../../research/iso-8601-week-date.md)).
The first Thursday is one of 1 … 7 January, and the Monday-to-Sunday week
around it holds 4 January exactly then — so **week 1's Monday is the Monday on
or before 4 January**, which is `days_from_civil(iy, 1, 4)` less 4 January's
weekday index. That form is derived, not quoted, and C-14 says so.

**One private function, `iso_week_one`, answers it, and every ISO field is
read off it in both directions**: the week-year is `y − 1` before `y`'s week-1
Monday, `y + 1` from `y + 1`'s, else `y`; the week number is whole weeks since
the week-year's first Monday, plus one; a week-year's week count is the
distance between two consecutive week-1 Mondays over seven — 52 or 53, never
tabulated; and `iso_week_to_date` adds `(w − 1) × 7 + (wd − 1)` to the
week-year's first Monday. So forwards and back cannot disagree about where a
week-year begins — **which is exactly why their round trip proves nothing on
its own** (§7, row D8), and why the sweep walks the rule the other way.

**The range's two ends, measured**: −9999-01-01 is a Monday, so it begins week
1 of −9999 and nothing in the range falls in week-year −10000; 9999-12-31 is a
Friday in week 52 of 9999, whose Saturday and Sunday are 10000-01-01 and -02,
so `iso_week_to_date(9999, 52, 6)` and `(9999, 52, 7)` are refused by
`days_to_date`'s range check, relayed. **Week 53 of a 52-week year is refused,
not read as week 1 of the next**: one date, one spelling.

```python
"""0.1.3's expected values (`0.1.3.md` §3), derived THREE WAYS that share no
code with `src/cal/cal.npk` or with each other, and then DIFFED against every

  P -- Python's `datetime` (`weekday()`, `timetuple().tm_yday`, `isocalendar()`)
       after a shift of whole 400-year cycles that is NEVER zero: 146 097 days
       is 20 871 weeks, so the shift moves no weekday and no week number, and
       a zero shift would make this the plain `datetime` on part of the domain.
  Z -- Zeller's congruence for the weekday, the leap rule and the month table
       for the day of the year, and ISO 8601's THURSDAY rule for the week date.
  C -- a count of days from -9999-01-01 over the leap rule, its weekday the
       count mod 7 from P's and Z's Monday (asserted), and ISO 8601's
       4-JANUARY rule for the week date.

Exit 0 only if the three agree on every date and every row the file states
equals them, in date order, with codes 10, 11, 12, ... ."""
import datetime, os, re, sys

VEC = os.environ.get("VEC", os.path.join(os.environ["REPO"],
                     "tests/unit/derived_field_vectors.npk"))


def leap(y):
    return y % 4 == 0 and (y % 100 != 0 or y % 400 == 0)


MDAYS = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]


def dim(y, m):
    return 29 if (m == 2 and leap(y)) else MDAYS[m - 1]


def ylen(y):
    return 366 if leap(y) else 365


YEARS = [-9999, -101, -4, -1, 0, 1901, 1969, 1970, 2004, 2008, 2011, 2012,
         2016, 2020]
DATES = []
for y in YEARS:                      # each year's 1 January, 31 December, next 1 January
    for dt in ((y, 1, 1), (y, 12, 31), (y + 1, 1, 1)):
        if dt not in DATES:
            DATES.append(dt)
DATES.append((9999, 12, 31))         # the range's last day
DATES.append((2018, 12, 31))         # ISO 8601-1:2019/Amd 1:2022's example
DATES.sort()


def P(y, m, d):
    for k in (1, 2, 25, 26, -1, -2):
        if k != 0 and 1 <= y + 400 * k <= 9999:
            break
    dt = datetime.date(y + 400 * k, m, d)
    iy, iw, iwd = dt.isocalendar()
    return (dt.weekday() + 1, dt.timetuple().tm_yday, iy - 400 * k, iw)


def zeller(y, m, d):                 # ISO weekday, Monday = 1
    if m < 3:
        m, y = m + 12, y - 1
    K, J = y % 100, y // 100
    h = (d + (13 * (m + 1)) // 5 + K + K // 4 + J // 4 + 5 * J) % 7   # 0 = Saturday
    return ((h + 5) % 7) + 1


def doy(y, m, d):
    return sum(dim(y, i) for i in range(1, m)) + d


def Z(y, m, d):
    wd, dy = zeller(y, m, d), doy(y, m, d)
    thu = dy - wd + 4                # the week's Thursday, as a day of year y
    if thu < 1:
        iy, thu = y - 1, thu + ylen(y - 1)
    elif thu > ylen(y):
        iy, thu = y + 1, thu - ylen(y)
    else:
        iy = y
    return (wd, dy, iy, (thu - 1) // 7 + 1)


def count(y, m, d):                  # days since -9999-01-01
    return sum(ylen(v) for v in range(-9999, y)) + doy(y, m, d) - 1


def C(y, m, d):
    n = count(y, m, d)

    def week_one(iy):                # the count of the Monday on or before 4 January
        j4 = count(iy, 1, 4) if iy <= 9999 else count(9999, 12, 31) + 4
        return j4 - (j4 % 7)
    iy = y - 1 if n < week_one(y) else (y + 1 if n >= week_one(y + 1) else y)
    return (n % 7 + 1, doy(y, m, d), iy, (n - week_one(iy)) // 7 + 1)


assert zeller(-9999, 1, 1) == 1 and P(-9999, 1, 1)[0] == 1     # the Monday, twice
bad, want = 0, {}
for dt in DATES:
    p, z, c = P(*dt), Z(*dt), C(*dt)
    if not p == z == c:
        bad += 1
        print("  DISAGREE  %s  P%s Z%s C%s" % (dt, p, z, c))
    want[dt] = p
print("%d dates; the three methods %s" % (len(DATES), "AGREE" if not bad else "DISAGREE"))

NUM = r"(0i64 - \d+i64|\d+i64)"
ROW = re.compile(r"^\s*r = raw row\(" + r",\s*".join([NUM] * 7) + r",\s*(\d+)i32\);", re.M)


def val(s):
    s = s.replace("i64", "")
    return -int(s.split("-")[1]) if "-" in s else int(s)


rows = [tuple(val(g) for g in m.groups()[:7]) + (int(m.group(8)),)
        for m in ROW.finditer(open(VEC, encoding="utf-8").read())]
if len(rows) != len(DATES):
    print("  COUNT     the file states %d rows; the derivation has %d" % (len(rows), len(DATES)))
    bad += 1
for k, (y, m, d, wd, dy, iy, iw, code) in enumerate(rows, 1):
    dt = (y, m, d)
    got = (wd, dy, iy, iw)
    ok = dt in want and want[dt] == got and code == 9 + k and (k == 1 or dt > (rows[k - 2][0], rows[k - 2][1], rows[k - 2][2]))
    bad += not ok
    if not ok:
        print("  MISMATCH  row %d %s states %s code %d; derived %s code %d"
              % (k, dt, got, code, want.get(dt), 9 + k))
print("stated rows: %d; disagreements: %d" % (len(rows), bad))
```

```nitpick
// neighbour of the calendar year for up to three days at either end -- 1
// January 2021 is in week 53 of 2020, and 31 December 2012 in week 1 of 2013.
```

### 5.4 The two refusal files

Each refusal sits beside an acceptance one step inside the same bound, so a
constructor that refused everything fails the file; each bound that moves is
tested where it moves — leap, common, a century that is not leap, year 0, a
negative year; and every argument is tested at both `int64` extremes, where
the arithmetic after the check would trap if the check came second.

## 6. The entry, the tags and the denominators

**The `sweep` entry needs no new `[[test]]`**: `tests/unit/sweep/` is already
its path (TM-166), so the two members join it by existing — which is also why
the harness runs them the moment step 2 writes them. What changes is the
manifest's COMMENT, which names the members and carries their domains' tags,
and the numbers the tree now measures differently.

**Every live statement of a new domain is tagged** (TM-168): the manifest's
sweep block, `CALENDAR.md` C-14 and C-15, `TESTING.md` V-2's two new rows, and
the CI header's new sentence — **eight new tags**, two per place, all
`domain_every_ordinal_date` or `domain_every_iso_week_date`, both 7 304 484.
**And one more, found at planning**: the CI header says *"re-exported together
as 50 public names"* with no tag, a present-tense statement of `lib_reexports`
that nothing diffed; it moves to 57 and gains its tag (TM-142's own rule).

**Three measured numbers move**, each at every tagged site and with the
untagged words beside it on the same line:

| Measured | Before → after | Sites |
|---|---|---|
| `npk_total` | 94 → **99** — two sweeps and three unit tests | `nitpick.toml`, `harness/run.py`, `BUILD.md` B-7b, `TESTING.md` §1 |
| `suite_roots` | 57 → **62** — the same five, all selected | `harness/run.py` |
| `lib_reexports` | 50 → **57** — the seven derived fields | `src/lib.npk`'s header, and the CI header's new tag |

**The threshold, set here and not after**: B-9's *"seconds, not minutes"* was
measured at 0.1.2 as 4.5 s for three units against a 30 s threshold. **This
subcycle keeps 30 s for the SUM of the five `sweep` units' times from one
full run** — the harness's own per-unit figures, not the whole run's wall
clock, which moves by more than any one unit. **Under 30 s: record it, and the
sweeps stay in the default run** — B-9 and B-9b decide that, and the number is
what B-9's premise now rests on. **Over 30 s: STOP and report**, because a
stage six times slower than 0.1.2's is a finding about the tree or the machine
before it is a scheduling question. The rehearsal's full run read 16.8 s —
under, with less headroom than 0.1.2's factor of six, so a loaded machine could
move it; that is why the threshold is on one full
run's own figures and not on a second run chosen for being faster.

**The ISO member is the long pole, and why is known**: every date costs about
ten evaluations of Hinnant's formula — `iso_week_year` two week-1 Mondays,
`iso_week_number` a third, `iso_week_to_date` two more and `days_to_date` —

function answering where a week-year begins, called from both directions, is
the design (§2.4), and 7 s at -O0 is inside the budget.

**Memory is not a risk**: nothing in any loop allocates but each program's one

way**: do not fan the members or the matrix out in parallel, and do not run two
harness invocations at once, on a machine where `earlyoom` has fired today.

```python
#!/usr/bin/env python3
"""0.1.3 and 0.1.3b (`0.1.3.md` §9 step 7, `0.1.3b.md` §7): draft labels become

    renumber.py FIRST_TM [FIRST_PD [COUNT]]      defaults: PD-20, eight labels

FIRST_TM is read by the plan's gate. Tracked AND untracked files (new tests
carry labels, and `git grep` skips untracked files unless told). Exact labels

for rel in files:

    path = os.path.join(REPO, rel)
```

# 0.0.2 — the harness, part 1 — DONE (2026-09-05)

> **Scope:** `harness/run.py` builds the library and judges a `program`-stage
> test by its exit code, at -O0 and again under `opt -O2`, with the toolchain
> pinned and the undefined-symbol scan as a build step. This is TM-003's runner
> and it retires into `npkg` when O-N1 closes.

## 1. Decisions taken at planning

- **P-12 — the harness reads `nitpick.toml` and never hardcodes a path.**
  Entry, output, opt-level, the four flag lists and the `[[test]]` table all
  come from the manifest, for the compiler's own D-204 reason: a stated flag
  nothing consumes is the next stale document. The one thing it takes from the
  environment is `NPKC`, the compiler to test with.
> **THREE OF THESE SEVEN WERE CORRECTED BY MEASUREMENT.** The original text
> stands, because it records what was believed when the work was planned; each
> correction is a numbered decision taken in the same commit as the work that
> revealed it. **P-14 → TM-118** (the allowlist's source), **P-16 → TM-117**
> (there is no separate compilation), and **§2's pipeline diagram → TM-117**.
> P-12, P-13, P-15 and P-17 survived intact.

- **P-13 — the undefined-symbol scan is a build step and fails the build**
  (`specs/BUILD.md` B-2), not a test that can be skipped. It reads the object's
  ELF64 symbol table directly rather than spawning `llvm-readelf`: a fourth
  tool outside the pin, whose text output nothing checks, is a poor foundation
  for a rule that is law. Python's `struct` reads an ELF symbol table in about
  forty lines.
- **P-14 — the allowlist is derived, not written.** Every `define` in
  `runtime/npkrt.ll` plus `main`. A written list goes stale the first time the
  floor gains a symbol.
  > **CORRECTED BY TM-118.** "Derived, not written" was right and the *source*
  > was wrong: the `.ll`'s 166 `define`s against the object's 111 globals is
  > 56 too many (`internal` linkage, which resolves nobody) and 2 too few
  > (`_start` and `npk_clone_raw`, from `module asm`). "Plus `main`" was short
  > as well — a library object legitimately needs `@npk_failsafe`, and the
  > first run of the scan failed on exactly that. The allowlist is derived from
  > `$NPKRT`'s own symbol table, both halves.
- **P-15 — `opt -O2` is a check leg on every program, always**
  (`specs/BUILD.md` B-3). The compiler's version of this instrument found a
  real defect on its first run that had passed for six cycles. A missing `opt`
  fails loudly rather than skipping.
- **P-16 — one build of the library per run, reused by every program.** The
  library compiles once to an object; each test program compiles and links
  against it. A per-test rebuild is the difference between a two-minute suite
  and a forty-minute one, and it is worth getting right before there are two
  hundred tests.
  > **CORRECTED BY TM-117: the remedy does not exist.** `npkc` has no
  > separate-compilation mode — one root in, the whole reachable graph out —
  > so a program's object already contains the library's, and linking both is
  > `ld.lld` exit 1 with 121 `duplicate symbol` lines. The library is still
  > built once per run, as a **check** rather than as an input. P-16's *reason*
  > survives, so the cost is measured instead: 27 units in 65 s, ~2.6 s per
  > program with both legs, printed on every run.
- **P-17 — `repro` is a first-class check here, not an afterthought.** The
  generated zone tables will be the largest source file in the tree
  (`ZONE_MODEL.md` §3), and a generator whose output varied by dictionary
  iteration order would break byte-identity in a way no other check would
  notice. Building it now means 0.5 inherits the check rather than adding it.

## 2. The pipeline

```
manifest ─► module graph ─► npkc  ─► ntime.ll
                                  ├─► opt -O2 ─► ntime.opt.ll   (check leg)
                                  └─► llc      ─► ntime.o
                                          └─► ELF undefined-symbol scan
per program: npkc ─► p.ll ─► llc ─► p.o ─► scan ─► ld.lld(p.o, ntime.o, npkrt.o) ─► run
```

> **THE LAST LINE IS WRONG AND WAS MEASURED SO (TM-117).** `ld.lld(p.o,
> ntime.o, npkrt.o)` is exit 1: 121 lines of `duplicate symbol`, the first
> `npk.prelude.int8:ToString.to_string`. The built pipeline is
>
> ```
> the library, once per run, linked into nothing:
>   src/lib.npk ─► npkc ─► ntime.ll ─► llc ─► ntime.o ─► scan
>                                └─► opt -O2 ─► ntime.opt.ll ─► llc -O2 ─► scan
> each program, its own whole graph:
>   p.npk ─► npkc ─► p.ll ─► llc    ─► p.o     ─► scan ─► ld.lld(p.o, npkrt.o) ─► run
>                        └─► opt -O2 ─► p.opt.ll ─► llc -O2 ─► p.opt.o ─► scan ─► link ─► run
> each refusal member (TM-119): npkc must FAIL with exactly the header's code set
> ```

## 3. Steps

1. **`harness/manifest.py`** — a minimal TOML reader (the manifest is small and
   the subset used here is a dozen lines), the schema check, and a loud refusal
   naming any key the schema lacks.
2. **`harness/toolchain.py`** — asks `llc --version`, `opt --version`,
   `ld.lld --version` and refuses a mismatch against `[toolchain] llvm`. Asks
   the tools, not `llvm-config`, which is a `-dev` package the build does not
   need.
3. **`harness/elf.py`** — the ELF64 symbol-table reader and the allowlist
   derivation from `runtime/npkrt.ll`.
4. **`harness/build.py`** — the pipeline above, every argv built from the
   manifest's flag lists.
5. **`harness/stages.py`** — the `program` stage: read `// expect-exit:`,
   `// stress: N` and `// argv:` from the file; run; compare; repeat under the
   optimised object.
6. **`harness/run.py`** — the driver: stage order, per-unit verdict lines,
   `--only`, `--verdicts PATH`, and a summary stating the counts.
7. **The `repro` check** — build twice from two working directories, compare
   the emitted `.ll` byte for byte, fail loudly on a difference.
8. **One real program** — a probe from 0.0.0, run as a `program`-stage entry,
   green under both legs.

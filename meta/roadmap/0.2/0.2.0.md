# 0.2.0 — `Instant`: the type, the clock tag, `instant_since`, and the refusals — PLANNED

> **Scope:** cycle 0.2's opening subcycle. `src/span/` stops being a
> placeholder: `Instant`, a reading of one of two clocks, and the four things a
> caller may do with readings — build one, subtract two of the same clock, add
> a `Duration`, compare two of the same clock. **The cycle README's 0.2.0 row
> ends with "a timeout cannot be written against a wall clock"**, and this plan
> makes that true the only way the language allows: there is no conversion
> between `Instant` and anything else, a consumer cannot build or edit an
> `Instant` by hand (the fields are sealed), and a probe asserts both refusals.
>
> **What it is not:** `Timestamp` (0.2.1), the conversions (0.2.2), the
> `Duration` constructors `ntime` adds (0.2.3), or the clocks themselves —
> `host_now_instant` and `host_now_boot` are cycle 0.3's, and they will build
> their answers through this plan's constructor. **Nor the re-pin**: the board
> moved the toolchain to `5fbaf4a` on 2026-09-27, and [`0.2.0a.md`](0.2.0a.md),
> the adoption, runs first; this plan was rehearsed over the tree it leaves.
>

### 1.3 What a consumer can do with it — both legs

`m2_use`: two readings of one clock built by `instant_of`, `instant_since`
between them (3 500 ns), `instant_add` of that `Duration` to the earlier one,

## 2. The decisions, and what chose each

| Label | Decision | Why this and not the alternative |
|---|---|---|
| **PD-53** | `Instant` is `{ sealed int64:ns; sealed InstantClock:clock; }`, and `InstantClock` is an enum, `{ Monotonic; Boottime; }`, each `#[derive(Eq, Clone, Debug, Copy)]`, neither `Ord`. Amends `TIME_MODEL.md` M-2 and `HOST.md` H-6 | **Sealed**, so a consumer cannot build an `Instant` from a number or edit one (`TYPE-079`, §1.4) — the type-level half of "a timeout cannot be written against a wall clock" — where M-2's bare field would let `Instant{ ns: wall_clock_ns }` compile. **An enum and not H-6's `uint8`**: a `uint8` holds 254 values that are no clock, and S-15c is this library's lesson that a tag outside an enum is a silent wrong answer. **No `Ord`**: a derived order compares readings of two clocks as though they were one — `instant_cmp` is the comparison, and it refuses. **`Copy`, added at the rehearsal at `5fbaf4a`**: `vec_at` takes the prelude's `T: Copy` since 0.2.0a (its PD-60), and an `Instant` owns nothing — an `int64` and a payload-free enum — so a consumer's `Vec` of readings reads back through the library's one by-value accessor (`NITPICK-TYPE-017` at each read without it, §1.2). Declined: M-2 as written (no clock, and TM-010.1 unbuildable); H-6's `uint8`; no `Copy` — a `Vec<Instant>` nothing in the library can read back |
| **PD-54** | The operations: `instant_of(ns, clock)` — `never fails`, public, the one constructor; `instant_since(later, earlier)` — FALLIBLE, `ETimeValue` for two clocks; `instant_add(t, d)` — `never fails`, overflow traps; `instant_cmp(a, b)` — FALLIBLE, `ETimeValue` for two clocks. The refusal's detail is `ValueFault.ClockMismatch`, appended to `cal`'s enum. **O-X3 settled: the clock is the sealed field, read anywhere; there is no `instant_clock` function.** Amends M-4 | **`instant_of` is public** because cycle 0.3's `host` must build readings (§7), and a module may not write another's sealed field; a caller who hands it a wall-clock reading has opted out, stated as C-8b states it for `CivilDate`. **Fallible where a pair can be two clocks** — TM-010.1 asks it of `instant_since`, and the same argument covers `instant_cmp`. **`instant_add` traps** on overflow, as `TIME_MODEL.md` §8's table has said since cycle 0.0: a reading 292 years past boot. **`ClockMismatch` in `cal`'s `ValueFault`** because `ETimeValue`'s detail enum IS `ValueFault` (S-3); how it is handed back stays O-X8's. **No accessor function**: one public name fewer, and a sealed field already is read-only exposure. Declined: `instant_since` `never fails` with a trap for two clocks — a stop where the caller can answer; an `instant_clock` function beside the readable field |
| **PD-55** | The S-6 generator qualifies an identity by the module that DECLARES it: for a `fail X` in module M, M.X if M declares X, else the one module in the imported subgraph that does; two or none is a problem the check reports, never a guess. A fourth calibration specimen, `probe11_relay_lib.npk`, raises an identity it imports | §1.6: the compiler's REACH-003 is the oracle (S-6b) and it names the declaring module; the generator named the site's. Found by this plan, latent until `span` raises `cal`'s identity. **Before step 2**, or `check_failsafe_arms` is red for the generator's reason. Declined: reading the qualification out of REACH-003 itself — S-6b's point is that the source computation is the thing under test |
| **PD-56** | The refusals are two probes, dispatched by their own headers (`BUILD.md` B-4c): `probe20_instant_literal_refused.npk` (`TYPE-079`, named twice — one line per site, B-7c) and `probe20b_instant_conversion_refused.npk` (`RESOLVE-002`). Not a `check`-stage entry | Every refusal the library asserts is a probe of this shape — `probe15`, `probe16` … `probe16i`, `probe19` — the rule `tests/probe/README.md` states since cycle 0.1's close (a probe about the language's verdict on the library imports the module it asks about). A `check` entry would put one kind of file in two directories. Declined: `tests/rejection/` and its first `[[test]]` entry — worth it the day a refusal is not a probe's kind |

### 4.2 `src/span/span.npk` — the code, measured in §1

```nitpick
mod:span;

use "../cal/cal.npk".ETimeValue;

#[derive(Eq, Clone, Debug, Copy)]
pub enum:InstantClock = { Monotonic; Boottime; };

#[derive(Eq, Clone, Debug, Copy)]
pub struct:Instant = { sealed int64:ns; sealed InstantClock:clock; };

pub func:instant_of = Instant(int64:ns, InstantClock:clock) never fails {
    pass Instant{ ns: ns, clock: clock };
};

pub func:instant_since = Duration(Instant:later, Instant:earlier) {
    if (later.clock != earlier.clock) { fail ETimeValue; }   // ValueFault.ClockMismatch
    pass raw duration_ns(later.ns - earlier.ns);
};

pub func:instant_add = Instant(Instant:t, Duration:d) never fails {
    pass Instant{ ns: t.ns + d.ns, clock: t.clock };
};

pub func:instant_cmp = Ordering(Instant:a, Instant:b) {
    if (a.clock != b.clock) { fail ETimeValue; }              // ValueFault.ClockMismatch
    if (a.ns < b.ns) { pass Ordering.Less; }
    if (a.ns > b.ns) { pass Ordering.Greater; }
    pass Ordering.Equal;
};
```

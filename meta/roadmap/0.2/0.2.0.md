# 0.2.0 — `Instant`: the type, the clock tag, `instant_since`, and the refusals — PLANNED

> **Scope:** cycle 0.2's opening subcycle. `src/span/` stops being a
> placeholder: `Instant`, a reading of one of two clocks, and the four things a
> caller may do with readings — build one, subtract two of the same clock, add
> a `Duration`, compare two of the same clock. **The cycle README's 0.2.0 row
> ends with "a timeout cannot be written against a wall clock"**, and this plan
> makes that true the only way the language allows: there is no conversion

### 1.2 The candidate module compiles — and the spellings it needs

The module in §4.2, compiled as a root: **`npkc` exit 0**, the `.ll` written.
The first draft was refused, and each refusal is a rule the worker would meet:

| Draft | Verdict | So |
|---|---|---|
| `#[derive(Eq, Clone, Debug)]` on `Instant`, none on the enum | `NITPICK-TYPE-019` ×3 — *"`InstantClock` has no method `eq`"* (and `clone`, `debug`) | a derive reaches each field's own impl: the enum derives the same three |
| `pass duration_ns(…)` inside a fallible function | `NITPICK-TYPE-007` — *"expected `Duration`, found `Result<Duration>`"* | a `never fails` callee is called `raw` from a fallible body |

`later.clock != earlier.clock` compiles: `!=` on a payload-free enum is
accepted.

**And `Copy`.** With `Copy` in both derives the module compiles, and an
`Instant` pushed into a `Vec<Instant>` reads back twice through `vec_at`. With
`Copy` dropped from both, the unit is refused `NITPICK-TYPE-017` at **six**
sites — the `Vec<Instant>` declaration, its turbofish, `vec_push`, the two
`vec_at` calls and `vec_free` — because since 0.2.0b the bound is the TYPE's
(`Vec<T: Copy>`); at 0.2.0a's tree it was the two `vec_at` calls alone. With
`Copy` on `Instant` alone, the derive is `NITPICK-TYPE-087`: a derive reaches
each field, as above. Block 0b measures both derive refusals, which until the
step rehearsal this section stated and nothing re-derived.

### 1.3 What a consumer can do with it — both legs

`m2_use`: two readings of one clock built by `instant_of`, `instant_since`
between them (3 500 ns), `instant_add` of that `Duration` to the earlier one,
`instant_cmp` of the sum with the later one (`Equal`), the clock read through
the sealed field, the later reading pushed into a `Vec<Instant>` and read back
twice through `vec_at` (PD-53's `Copy`), and the two refusals —
`instant_since` and `instant_cmp` of a `Boottime` reading against a
`Monotonic` one each `is_error`. **Exit 0 at -O0 and after `opt -O2`.** A root
importing `span` and `core/vec` owes **12** identities — §1.5's eleven and
`LimitViolated`, `Vec`'s `ListLen` — so the unit's `failsafe` names twelve.

### 1.4 What a consumer cannot do — the refusals

| Program | Verdict |
|---|---|
| `m4_literal` — `Instant{ ns: 1000i64, clock: InstantClock.Monotonic }` in a consumer | **`NITPICK-TYPE-079`**, once per field — two reports, both at the literal's position — each with a note at the field's declaration. ## 2. The decisions, and what chose each

Four, recorded by step 5's patch as the four TM numbers after 0.2.0b's, in PD
order, under a batch heading for the cycle; their full texts, every alternative
included, are `step5.patch`'s `meta/DECISIONS.md` hunk. §1 is their evidence.

| Label | Decision | Why this and not the alternative |
|---|---|---|
| **PD-53** | `Instant` is `{ sealed int64:ns; sealed InstantClock:clock; }`, and `InstantClock` is an enum, `{ Monotonic; Boottime; }`, each `#[derive(Eq, Clone, Debug, Copy)]`, neither `Ord`. Amends `TIME_MODEL.md` §2 and M-2 and `HOST.md` H-6 | **Sealed**, so a consumer cannot build an `Instant` from a number or edit one (`TYPE-079`, §1.4) — the type-level half of "a timeout cannot be written against a wall clock" — where M-2's bare field would let `Instant{ ns: wall_clock_ns }` compile. **An enum and not H-6's `uint8`**: a `uint8` holds 254 values that are no clock, and S-15c is this library's lesson that a tag outside an enum is a silent wrong answer. **No `Ord`**: a derived order compares readings of two clocks as though they were one — `instant_cmp` is the comparison, and it refuses. **`Copy`**: since 0.2.0b `Vec` is `Vec<T: Copy>`, so without it a `Vec<Instant>` is refused at the type, its turbofish and every verb (six sites in the unit, §1.2); an `Instant` owns nothing — an `int64` and a payload-free enum. Declined: M-2 as written (no clock, and TM-010.1 unbuildable); H-6's `uint8`; unsealed fields; `Ord`; no `Copy` — a `Vec<Instant>` nobody can write |
| **PD-54** | The operations: `instant_of(ns, clock)` — `never fails`, public, the one constructor; `instant_since(later, earlier)` — FALLIBLE, `ETimeValue` for two clocks; `instant_add(t, d)` — `never fails`, keeps `t`'s clock, overflow traps; `instant_cmp(a, b)` — FALLIBLE, `ETimeValue` for two clocks. The refusal's detail is `ValueFault.ClockMismatch`, appended to `cal`'s enum. **O-X3 settled: the clock is the sealed field, read anywhere; there is no `instant_clock` function.** Amends M-4, §9's lattice and `SAFETY.md` S-3 | **`instant_of` is public** because cycle 0.3's `host` must build readings (§7), and a module may not write another's sealed field; a caller who hands it a wall-clock reading has opted out, stated as C-8b states it for `CivilDate`. **Fallible where a pair can be two clocks** — TM-010.1 asks it of `instant_since`, and the same argument covers `instant_cmp`. **`instant_add` traps** on overflow, as `TIME_MODEL.md` §8's table has said since cycle 0.0: a reading 292 years past boot. **`ClockMismatch` in `cal`'s `ValueFault`** because `ETimeValue`'s detail enum IS `ValueFault` (S-3); how it is handed back stays O-X8's. **No accessor function**: one public name fewer, and a sealed field already is read-only exposure. Declined: `instant_since` `never fails` with a trap for two clocks — a stop where the caller can answer; `instant_cmp` ordering two clocks by their numbers; an `instant_clock` function beside the readable field; an enum of `span`'s own for the detail; `instant_of` private |
| **PD-55** | The S-6 generator names an identity by the module that DECLARES it: for a `fail X` in module M, M.X if M declares X, else D.X for the one module D in the imported subgraph that does; two or none is a `BuildError` naming the site, never a guess. A fourth calibration specimen, `probe11_relay_lib.npk`, raises an identity it imports — a support module at `none` in `EXPECT_EXEMPT`, held to 7 by part C. Amends `SAFETY.md` S-6b (its table and a fourth constraint) and `TESTING.md` V-14d | §1.6: the compiler's REACH-003 is the oracle (S-6b) and it names the declaring module; the generator named the site's. Found by this plan, latent until `span` raises `cal`'s identity. **Before step 2**, or `check_failsafe_arms` is red for the generator's reason. Declined: reading the qualification out of REACH-003 itself — S-6b's point is that the source computation is the thing under test; the first declaring module found — a guess; the fix without a specimen — calibrated only on the code it was found under |
| **PD-56** | The refusals are two probes, dispatched by their own headers (`BUILD.md` B-4c): `probe20_instant_literal_refused.npk` (`TYPE-079`, named twice — one line per site, B-7c) and `probe20b_instant_conversion_refused.npk` (`RESOLVE-002`). Not a `check`-stage entry | Every refusal the library asserts is a probe of this shape — `probe15`, `probe16` … `probe16i`, `probe19` — the rule `tests/probe/README.md` states since cycle 0.1's close (a probe about the language's verdict on the library imports the module it asks about). A `check` entry would put one kind of file in two directories.
```nitpick
mod:span;

use "../cal/cal.npk".ETimeValue;

#[derive(Eq, Clone, Debug, Copy)]
pub enum:InstantClock = { Monotonic; Boottime; };

#[derive(Eq, Clone, Debug, Copy)]
pub struct:Instant = { sealed int64:ns; sealed InstantClock:clock; };

pub func:instant_of = Instant(int64:ns, InstantClock:clock) never fails {
    pass Instant{ ns: ns, clock: clock };
};

pub func:instant_since = Duration(Instant:later, Instant:earlier) {
    if (later.clock != earlier.clock) { fail ETimeValue; }   // ValueFault.ClockMismatch
    pass raw duration_ns(later.ns - earlier.ns);
};

pub func:instant_add = Instant(Instant:t, Duration:d) never fails {
    pass Instant{ ns: t.ns + d.ns, clock: t.clock };
};

pub func:instant_cmp = Ordering(Instant:a, Instant:b) {
    if (a.clock != b.clock) { fail ETimeValue; }              // ValueFault.ClockMismatch
    if (a.ns < b.ns) { pass Ordering.Less; }
    if (a.ns > b.ns) { pass Ordering.Greater; }
    pass Ordering.Equal;
};
```

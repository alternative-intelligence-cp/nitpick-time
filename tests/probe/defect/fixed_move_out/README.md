# `fixed_move_out` — a move out of `fixed` storage compiles, and faults

**Raised at cycle 0.1.3b, 2026-09-25: the workbench registry's O-N20, and the
compiler's DEF-99.** The planner raised it by path, as `PLAYBOOK.md` asks of a
worker, and the orchestrator registered it (`../../../../../meta/OPEN_QUESTIONS.md`;
this repository's entry is `../../../../meta/OPEN_QUESTIONS.md` O-N20). The
compiler seat confirmed it the same day as DEF-99, and its fix — the move
refused at compile time, **`NITPICK-TYPE-084`** — is the compiler's 1.6.0 step
3f, **not landed when this was written and at no pin of this repository**:
every verdict below is `c3bdae2`'s, and `c3bdae2` accepts the move. The seat
measured its fixed compiler on these four files — cases 1 to 3 refused
`TYPE-084`, case 4 exit 0 — per the advance notice the workbench's board
carries with the compiler's notice 56.

## The defect

**A `move` out of an element, a row's field or a scalar of `fixed` storage
holding an owning value compiles at every pin this repository has kept — and
the program faults.** `fixed` storage is emitted as an LLVM `constant` global.
For an element or a field, the move then stores the vacancy —
`zeroinitializer` — into that constant, which is undefined behaviour in LLVM
IR: at -O0 the store hits read-only memory and the process takes SIGSEGV,
which `c3bdae2`'s runtime turns into `MachineFault`; under `opt -O2` the store
is deleted, as UB may be, the program runs on, and the moved string is later
dropped, freeing bytes the allocator never handed out, which it stops as
`Unreachable`. For a scalar no vacancy is written at all, so a second move
would be a second owner, and the first drop stops the same way.

**A plain `pass` is a move** — `pass NAMES[i]` from a function returning
`string` moves the element implicitly, the language behaving as specified
(`SAFETY.md` S-18d is the same fact for `vec_at<T>`) — so the shape that
reaches this defect need not say "move" anywhere.

What the language DOES refuse is the copy: `NITPICK-TYPE-046` on a by-value
read of an owning row or element (`../../probe17b_fixed_row_copy_refused.npk`,
`../../probe17c_fixed_string_copy_refused.npk`). **The fix this asks for is
the same kind of refusal for the move**: a `fixed` binding is immutable, and
moving out of it writes it.

## The cases, at `c3bdae2`

| File | What it does | -O0 | `opt -O2` | Asserted as |
|---|---|---|---|---|
| `case1_element_move.npk` | `move(NAMES[1])`, then drops it | **107**, `MachineFault` | **95**, `Unreachable` | `EXPECT_EXEMPT`, `run:107` |
| `case2_element_pass.npk` | `pass NAMES[i]` from a function, then drops it | **107** | **95** | `EXPECT_EXEMPT`, `run:107` |
| `case3_scalar_move.npk` | `move(V)` of a `fixed string`, then drops it | **95** | **95** | `EXPECT_EXEMPT`, `run:95` |
| `case4_clone_control.npk` | the same three reads by `.clone()`, dropped, twice | 0 | 0 | `// expect-exit: 0` |

**The control is what makes this a reproduction and not an anecdote**: the same
tables, the same strings, the same drops, and only the move replaced by
`.clone()` — exit 0 on both legs at every pin. So what faults is the move.

**No case carries an `expect-exit:` of its fault**, which would make a fault a
committed expectation of this suite; each is in `harness/run.py`'s
`EXPECT_EXEMPT` at its -O0 verdict, re-derived on every full run by
`check_exemptions_live` (TM-137). The day a pin carries DEF-99's fix, all
three verdicts MOVE to `npkc`, the harness names each, and each takes
`// expect-error: NITPICK-TYPE-084` — as `generic_owning_copy/` did when O-N19
landed (TM-154) — while case 4 keeps its `expect-exit: 0`.

## At every kept pin

`TRANSCRIPT.txt` has every file of this directory and the three `probe17`
files at `0dfddac`, `94874ce`, `950bb1d`, `aaffb87`, `3d15ac9` and `c3bdae2`, both
legs, generated by `meta/roadmap/0.1/0.1.3b.md` §3's `transcript.py`. In short:
**the move compiles at all six**; at -O0 the element cases die by SIGSEGV
(139) at four, stop as `Unreachable` at `950bb1d`, and as `MachineFault` at
`c3bdae2`, the first pin whose runtime handles the signal; under `opt -O2` they
stop as `Unreachable` at all six; the scalar case is `Unreachable` everywhere;
the copies are refused `TYPE-046` everywhere; the control runs clean
everywhere. **Not a regression** — it has been there as long as this
repository has kept a pin.

## What it blocks here

Nothing today: no `fixed` table in `src/` holds an owning value, and
`SAFETY.md` S-19b and `check_no_owning_fields` keep it so. It bears on cycle
0.5's version string (`ZONE_MODEL.md` Z-4, Z-6), which `../../../../meta/OPEN_QUESTIONS.md`
O-X10 holds until this is fixed.

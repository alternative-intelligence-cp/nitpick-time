### 1.6 How the lexer reads a literal, and the reader that follows it

Read at `5fbaf4a` (§0.3): a token that begins with a decimal digit — which no
identifier may, D-147 — runs on through letters, digits and `_`; a `.` followed
by a digit makes it a float, whose extent runs on through the same and one sign.
An integer's value is `num_scan`'s: the longest of `num_width_of`'s thirty-seven
width suffixes stripped, something left before it; then a base suffix, `hex`,
`bin`, `oct`, `ter`, `tri`, `non`, then `t` and `n`; `_` ignored wherever it
stands; the digits read in the base — balanced ternary's `T`/`t` is −1,
balanced nonary's `a`…`d` and `A`…`D` are −1…−4. A character literal is a
numeric token whose value is its code point, and widens. Python's `int()`
accepts `1_000_000` and refuses `86__400`, which the compiler accepts — a reader
that leaves the separators to it is right on one and wrong on the other.

`nitpick-regex`'s PD-46 (its plan at `15c82ee`, §1.2) reads the same lexer for
the same blindness in its own check, whose subject is a literal beside a
comparison; this check's subject is every literal in `src/`, so the reader here
tokenises the whole blanked text and evaluates every integer, and reports a
float or a token the lexer refuses by its text, never passing one. Regex's §1.2
counts a width past `u64` and a literal left of the comparison among what its
check passed; this check saw both (§1.5). Run over `src/` and `tests/`, the
reader reads **114 285** numeric literals and every one evaluates (block 7).

## 4. The code

### 4.1 What the instruments read, and what they may not do

Each check reads the tree it is POINTED AT — a scratch tree in the self-check,
the repository in a run — and imports nothing of it: `check_check_registry`
reads `harness/*.py` through `ast` and `TESTING.md` as text;
`check_no_view_returns` and `check_int128_sites` read `src/` through
`lexical.read` and `blank_code`, as every tree check does (V-1k, V-1l), and the
two documents as text (V-1k's third way); `check_constants_named` reads every
literal through `literals()`, which takes `lexical.spans` and evaluates what the
lexer would. None compiles anything; part E's third half is the self-check's
compile, and it is the pinned compiler's own `run:0` it requires. **`src/`
changes in comments only**: `limits.npk`, `cal.npk` and `bytes.npk`'s notes. No
`#wild_slice` is added to `src/` or `tests/` — the tree's fourteen stay
fourteen; the exemption's scratch plant spells `bytes_view`'s own line in a file
no stage compiles.

### 4.2 The registry's reading

`_registry_doc` finds `## 2. ` in `TESTING.md` and reads every pipe-table to the
next `## `: a table headed `| Check |` is the family, one headed `| Pending |`
V-1a's pending table, each row's FIRST cell's backticked name its check — a row
without one is a finding — and a pending row's second cell its cycle.
`_registry_harness` parses `checks.py`, `arms.py` and `run.py`: `LIVE`'s names,
`PENDING`'s `(name, cycle)` pairs, every `check_…` definition in the three, and
every name `run.py` calls; `registry()` keeps the calls a row names or the three
files define. The four statements are then three lists and a dict, diffed both
ways — and the headline is V-1a's arithmetic: *"20 row(s) in §2 = 13 in
`checks.LIVE` + 4 driven by `run.py` + 3 pending"* after step 4.

### 4.3 The literal reader

`literals(text)` blanks comments and every non-numeric literal by
`lexical.spans`, then walks the code: a run of `[0-9A-Za-z_]` not preceded by
one is a token; one that starts with a digit is a number — a float if `.` and a
digit follow, extended through the run and one sign, and not evaluated — and
`literal_value` evaluates the rest: the longest of the thirty-seven widths (two
to six characters, something left before it), then the first base suffix that
matches in `num_scan`'s order, then each digit in the base, `_` skipped, a digit
out of the base `None`. Character literals come from `lexical.spans`' `char`
kind, decoded by `lexical`'s own escape reader. The check then holds
`abs(value)` to `CONSTANT_OWNER`; `None` is a finding by its text. Step 7's
patch has the code.
